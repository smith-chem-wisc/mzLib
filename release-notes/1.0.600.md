# mzLib 1.0.600 — a differential statistics runner, MassIVE deposits and ProteomeXchange search, PRIDE over Aspera, calibrated `.msl` retention times, and MGF native IDs
**Source:** `1.0.599..1.0.600` (`6fc4153f..f6358d02`, 21 PRs)
**Contributors:** @acesnik, @trishorts

**MetaMorpheus can take this release with a pin change alone.** No package dependency or target framework changed, no
DLL was added (#1612's Aspera key is embedded in `UsefulProteomicsDatabases.dll`), and `mzLib.nuspec` is unchanged.
mzLib's `integration` job built MetaMorpheus master (`0da8edeaf`, 1.1.15) against these PRs (run 44936641623): 4,086 of
4,089 tests passed, 3 were skipped, none failed. Two of its answers still change with the bump: label-free protein values
lose the values median polish used to invent (#1607), and a TMT run whose every match is ambiguous only in its
modification sites is now quantified (#1602).

**The differential statistics are in the package, and nothing calls them yet.** The runner (#1591) has no caller in
MetaMorpheus, FlashLFQ or dataRepo. The set test is missing its share model (S4b) and its output files (S5), and its
pooled standard error can be far too small until #1616, which is **not** in this release.

Answers change for existing callers in these places:
- median-polish protein values, and so FlashLFQ's and MetaMorpheus's label-free protein tables (#1607);
- `QuantificationEngine`, which no longer writes isobaric tables for a design that is not isobaric (#1610);
- the set test, which now fits robustly by default (#1592), and `DifferentialResults.tsv`, which gains a column (#1591);
- a DIA precursor quantity of 0, which now reads as no value (#1614);
- MGF spectra, which now have native IDs, and MGF source-file names (#1613);
- `MPD:`, `Any:` and numeric keys in a modifications file (#1182);
- MassIVE listings, which now fail instead of coming back short (#1609).

## Breaking changes

- **Rebuild against this release (#1592, #1603).** Each of these gained a last optional parameter, and no overload of
  the old shape was kept:
  - `RandomEffectsMeta.Pool`: `RandomEffectsInference inference = Normal` (#1603). The default gives 1.0.599's numbers.
  - `SetModel.FitSet`: `bool robust = true`, after `out string? notRun` (#1592).
  - `SetTest.Run`: `bool robust = true` (#1592). The default changes the answer; see **Changed answers**.

  Source compiles unchanged. A binary built against 1.0.599 throws `MissingMethodException` until it is rebuilt.
  MetaMorpheus calls none of these.

## Changed answers

- **Median polish no longer invents a protein value for a sample it cannot place (#1607).** Take a sample whose
  peptides were each seen only in that sample, in a group where another peptide was seen in two or more samples. When it
  was the only such sample, `MedianPolishRollUp.QuantifyGroup` gave it the group's reference level, whatever it
  measured: 2828.43 for X = 50, 5,000 or 5,000,000 in the PR's example. It is now NaN ("observed but unquantifiable"),
  and the `MedianPolishRollUp` strategy writes it as 0.
  - Every `FlashLfqEngine.Run` uses it, so MetaMorpheus's `AllQuantifiedProteinGroups.tsv` changes: such a cell is now
    blank. The glyco and SILAC paths take it too.
  - On a 4-file label-free islet search, 171 of the 2,302 target groups with values in two or more files (7.4%) carried
    an invented value, 171 of 8,034 cells with data. Exactly those cells become NaN, and none of the other 11,025 change.
  - A sample whose fitted effect is exactly 0 now keeps its value. Before, two such samples were both blanked.
  - **What does not change:** single-file runs, groups with no peptide seen in two samples (#1486's rule), and every
    sample the fit can place. Groups whose samples fall into sets no peptide joins (7 on that search) are left for a
    later decision.
- **`QuantificationEngine` writes `RawQuantification.tsv`, `PeptideQuantification.tsv` and
  `ProteinGroupQuantification.tsv` only for an isobaric design (#1610).** Their write flags default to on, so a
  label-free or DIA run wrote tables whose names say TMT, and dataRepo switches to isobaric ingest on those names.
  - `Run()` now returns `Success = false` and writes nothing when any write flag is on and any sample is not an
    `IsobaricQuantSampleInfo`, a design that mixes TMT channels with one label-free file included.
  - **A label-free caller that leaves `WriteRawInformation`, `WritePeptideInformation` and `WriteProteinInformation`
    at their defaults now fails,** with or without an `OutputDirectory`. Set all three to false to quantify without
    writing.
  - Isobaric runs, runs with writing off, and an empty design are unchanged. MetaMorpheus's only design here is
    isobaric, so it sees no change.
- **The set test fits robustly by default (#1592).** In 1.0.598 and 1.0.599, `SetModel.FitSet` and `SetTest.Run` fitted
  the set model without weights. Now they reweight as msqrob2 does (#1499), STAT1's setting.
  - A set whose reweighting does not settle is fitted on the first round's weights (#1547) and flagged by
    `SetEstimate.RobustFellBack`. Only a first round that cannot be formed is still `not_run`.
  - On the R fixtures, β̄ moves from 0.28901 to 0.29737 (balanced) and from 0.18417 to 0.19176 (missing). Weights and
    fits match R within 1e-6. Pass `robust: false` for the old fit.
  - `SetEstimate` gains `Robust`, `RobustFellBack` and `Weights`.
- **`DifferentialResults.tsv` gains a column, and every analysis id changes (#1591).**
  - `DifferentialResultWriter` writes `robust_fell_back` as column 53 of 57, between `robust` and `normalization`. A
    reader that finds columns by position, or expects a fixed count, fails.
  - The metadata's settings gain `minimum_samples_per_side` (2) and `normalization_floor` (100). The settings feed
    `AnalysisId`, so the same inputs and settings now give a new id (the golden file's: `adc8979a883969aa` to
    `f0276d430c1a7002`).
- **A DIA precursor quantity of 0 reads as no value (#1614).** `DiaPrecursorFromTsv.PrecursorQuantity`, like the new
  `Ms1Quantity`, stores null for a 0, from a file or from code. Every 0 MetaMorpheus's DIA search wrote meant nothing
  was measured.
  - `AllDiaPrecursors.tsv` written by `DiaPrecursorFile` gains five trailing columns: `Quantity State`,
    `Quantity Floor`, `MS1 Quantity`, `MS1 Quantity State` and `MS1 Quantity Floor`. A table without them still reads.
- **MGF spectra now have a native ID, `index=<the block's zero-based position in the file>` (#1613).** This is PSI-MS's
  MS:1000774, which mzIdentML and PRIDE use for MGF. In 1.0.599 `MsDataScan.NativeId` was null for every MGF spectrum.
  A block with no peaks is still dropped but keeps its position, so scan numbers and native IDs are not derivable from
  each other: in `tester.mgf`, scans 14, 19, 20, 21 and 2 are `index=0` to `index=4`.
  - `Mgf.GetSourceFile()` says `multiple peak list nativeID format` and `Mascot MGF format`, where it said
    `no nativeID format` and `mgf format` (the new constant `Mgf.NativeIdFormat` holds the first). Code that matched the
    old strings stops matching.
  - `ExportAsMzML` of an MGF writes spectrum ids `index=0`, `index=1` and so on, where it wrote none. `ExportAsMgf`
    writes `NativeID:"index=N"` into each TITLE, where it wrote `NativeID:""`.
  - Scan numbers, peaks and every other reader are unchanged. MetaMorpheus's mzIdentML still writes MGF results as
    `scan=<scan number>`, so its output does not change with the bump.
- **`MPD:` and `Any:` in a modifications file now read as the format intends (#1182)**, on the `NL` and `DI` lines
  `ModificationLoader` reads.
  - `MPD:` gives `IRMPD`. 1.0.599 gave `MPD` (MS:1000435), because the guard meant to map it never ran.
  - `Any:` gives `AnyActivationType`. In 1.0.599 it failed to parse, and the modification silently lost every
    diagnostic ion and neutral loss on that line.
  - Only member names parse now, in any case. A numeric key (`7:`) or a comma-joined one (`CID,HCD:`) fails, and the
    modification loses that line's values, as with any unknown key. The rule is public as
    `ModificationLoader.ParseDissociationType`.
  - **What does not change:** no file mzLib ships uses these keys (`Mods.txt` uses `HCD` and `ETD`, `TMT.txt` uses
    `HCD`), so default modifications load as before, masses included.
- **The obsolete `PtmListLoader` forwards to `ModificationLoader` and gives its answers (#1182).**
  `ModDissociationType` resolves 14 names it returned null for (`PD`, `UVPD`, `LowCID`, `Autodetect` and others) and
  ignores case; the nine names it handled keep their values. `ReadModsFromFile` returns `BM` and `BL` entries as
  `BackboneModification` and `BaseModification`, where it dropped them (the shipped `RnaMods.txt` has 4 and 6).

## New

- **`DifferentialAnalysis.Run(DifferentialRequest)` turns a quantified search into differential-abundance results
  (#1591).**
  - **Input:** a label-free `ObservationTable` or an `IsobaricObservationTable`, before normalization, with the samples,
    design, comparisons and settings.
  - **Output:** `DifferentialAnalysisResult.Write` writes `DifferentialResults.tsv` and its metadata,
    `DifferentialDecisions.tsv` (every place a rule changed what happened, and why), then `StatisticalReport.md` and
    its figures.
  - **The rules** are QuantProject's STAT1 rulings 1–18: target groups at 1% protein q-value, only peptides unique to
    the group with values in at least 2 samples; two or more peptides, a peptide-level mixed model with robust weights
    and Satterthwaite df; one peptide, limma's moderated t; one variance prior per model family; Benjamini–Hochberg per
    comparison family.
  - **Checked against R:** on the fixtures, every one of the 226 rows R fits, effects within 1e-6, SE and p within 1e-4
    relative. On PXD007683 (TMT11, 6,959 proteins), estimates within 2.2e-7 log2 and SE within 1% on 99.99% of rows. On
    the MSstatsTMT mixtures, estimates within 2.4e-5.
  - **Nothing calls it yet.** MetaMorpheus, the FlashLFQ app and dataRepo are each to call it in their own PR.
- **The set test: pooling, the families, and the first half of the isoform-share test (#1603, #1605).** QuantProject's
  SETTEST1 milestones S3 and S4a. The share model (S4b) and the output files (S5) are not in this release.
  - `SetPooling.Run` (#1603) picks each hypothesis part's primary result from the freeze's flags, pools two or more
    datasets by DerSimonian–Laird with a Hartung–Knapp standard error on t(k − 1), forms the aging and maturation
    Benjamini–Hochberg families, and adjusts each supported part's datasets by Benjamini–Bogomolov. It matches metafor
    and `p.adjust` within 1e-8.
  - **In this release, the pooled row's standard error can be far too small.** Plain Hartung–Knapp measures only how
    far apart the datasets' estimates sit: two datasets at 1.000 and 1.001 log2, each with se 0.3, pool to se 0.0005
    and a one-sided p of 0.00016, although each alone has p = 0.004. #1616, not in this release, uses the larger of that
    and DerSimonian–Laird's. **Do not act on a pooled `supported` until #1616 is released.**
  - The share test's first half (#1605): `ShareRegionReader` reads the regions a freeze's `marker_region` names, and
    `ShareSequenceIndex` with `SharePeptideClassifier` classes each peptide as marker, reference or neither from the
    searched database, reading I and L as one residue. `ShareMemberStates` says whether each member can be tested, and
    why not. On aging's 21 share rows, all 27 named markers pass.
- **Three statistics helpers (#1603)**, each additive with its default unchanged:
  `RandomEffectsMeta.Pool(..., RandomEffectsInference.HartungKnapp)` (its result gains `Inference` and
  `DegreesOfFreedom`; one study is refused), `MultipleTesting.BenjaminiBogomolov`, and
  `PValueCombination.FisherPartialConjunction(p, u)`.
- **`IsobaricMassTag.GetReporterIonReadings(MsDataScan)` tells a reporter ion below the scan's floor from one the scan
  never recorded (#1606).** `GetReporterIonIntensities` gives 0 for both, and it is unchanged.
  - Each channel's `ReporterIonReading` holds the intensity (NaN unless the kind is `Value`), the kind (`Value`,
    `BelowFloor` or `NotRecorded`) and the floor, from the noise table, else the weakest peak between the reporter ions,
    else the weakest peak in the scan (`FloorSource` says which).
  - On the repository's TMT11 SPS-MS3 file, all 407 channels of the 37 ion-trap MS2 scans are `NotRecorded`, where
    `GetReporterIonIntensities` gives 0. The 37 Orbitrap MS3 scans give 405 values and 2 `BelowFloor`.
- **A DIA precursor quantity from selected, interference-corrected fragments (#1614).** MetaMorpheus's DIA search sums
  every library fragment, which pulls ratios toward 1:1: on PXD071205's 5-minute HYE runs, yeast A/B (expected log2 +1)
  reads +0.65, against DIA-NN's +0.88.
  - `FragmentQuantity` works on traces a search already extracted: `Area`, DIA-NN's `InterferenceCorrectedAreas`,
    `SelectAcrossRuns` and `Quantify`, whose `PrecursorQuantity` is `Value`, `BelowFloor` or `NotLooked`, never 0.
  - On planted traces an interferer puts the plain sum 52–258% high; the corrected sum stays within 10%. Which fragments
    to sum is still to be chosen on the HYE benchmark.
- **What a MassIVE deposit holds, and keyword search across ProteomeXchange (#1608)**, on 1.0.598's `MassiveClient`.
  - `Readers.MassiveRuns.Of(listing)` names a deposit's runs, each a `MassiveRun` with its primary file and members. A
    `.d` folder or a Waters `.raw` folder is one run; other files group by folder and by the SDRF drafter's stem; vendor
    runs come before `.zip`s, and `.zip`s before peak lists; `ccms_peak` is never a run; a search-only deposit has none.
    On 13 real listings, MSV000093798 has 192 `.raw` runs, and MSV000090777 has 50 SCIEX runs, each a `.wiff` with its
    sidecars.
  - `MassiveFileExtensions.IsDepositedSdrf`, `IsDesignTableCandidate` and `IsSpectronautOutput` sort listed files by
    name. `MassiveParameters.Read` reads four fields of `params.xml` (workflow, upload map, species, instruments); it
    never returns the e-mails or a reviewer password, and it refuses DTDs.
  - `MassiveClient.SearchDatasetsAsync(keyword, speciesTaxId)` finds MassIVE datasets with no PXD ("zebrafish": 67, 48
    of them without one). `ProteomeCentralClient.SearchDatasetsAsync(keyword, filter)` searches every ProteomeXchange
    repository; its species filter takes a name, and a taxonomy ID is refused. `RepositorySearch.Merge` joins the two
    and says which found each dataset.
- **Downloads from PRIDE over Aspera (#1612).** HTTPS downloads and their retries work as before.
  - `PrideArchiveClient.DownloadFileViaAsperaAsync` runs IBM's `ascp` (4.4.4 or newer, at
    `PrideAsperaOptions.AscpPath`; mzLib neither bundles it nor looks for it) once against EBI and checks the copy
    against PRIDE's checksum row. A failure is a `PrideAsperaException` whose `Failure` is `LoginRefused`,
    `CannotConnect`, `Stalled`, `DamagedCopy` or `AscpFailed`. It derives from `HttpRequestException`, and
    `ServiceFailure.IsTransient` is true for every kind, a damaged copy included; over HTTPS a damaged copy is an
    `MzLibException`.
  - `DownloadFileWithPolicyAsync` (opt-in) tries Aspera, then HTTPS: 8 tries, waits growing by 15 s. After EBI refuses a
    login or a connection, Aspera is set aside for the process for 30 minutes, and at most 3 Aspera sessions run at
    once. PXReprise measured about 3–4 MB/s from one Aspera session, against about 2 MB/s from four HTTPS streams.
  - EBI's public key for anonymous downloads (1,679 bytes, pinned by SHA-256) is embedded in
    `UsefulProteomicsDatabases.dll`, its licence in `THIRD-PARTY-NOTICES.md`. It is a `BEGIN RSA PRIVATE KEY` block, so
    a secret scanner run over build output or an installer may flag it; it is EBI's published anonymous key.
- **`MslPredictedRetentionTimes.Assign` gives `.msl` entries a predicted iRT (#1590).** A predicted time has status
  `None`, so the first measured time from `UpdateRetentionTimesAndSave` replaces it.
  - A peptide of up to 30 residues, with any modifications, gets the iRT predictor's value; an unmodified one of 31–50
    residues gets the optional long-peptide predictor's; any other gets NaN. Fixed carbamidomethyl C counts as
    unmodified.
  - `ReplaceAll` rewrites every time and status, for a library whose times cannot be used, such as one converted from
    `.msp` (its times are minutes in one unnamed run, though `MslConverter.FromMspFile` labels them iRT).
    `FillMissing` touches only entries with a NaN time and status `None`, so it can be repeated after a Koina outage; it
    does not touch a converted `.msp`, whose minutes are not NaN.
  - `FromKoina(model)` wraps a Koina iRT model (for example `Prosit2025iRT40PTM`), sending ProForma so a modification
    reaches the model by its Unimod id; a model that predicts minutes is refused. `ChronologerOnIrtScale(knownIrt)` maps
    local Chronologer's % acetonitrile onto iRT by a robust fit, and throws when fewer than 20 peptides survive.
  - `Assign` returns copies. Its `Source` is left as it is: set `Empirical` yourself when the spectra were measured.
- **`MslLibrary.UpdateRetentionTimesAndSave` corrects a library's times from one dataset's identifications, then writes
  the result (#1589).** Until now a library's time was the last search's best scan, in that run's minutes, unchecked.
  Per the PR, the human library built with these rules gave 4.8 to 5.0% more DIA identifications at 1% FDP.
  - Each run is calibrated onto iRT on its own, from about 1,000 unmodified 7–30-residue anchors against their predicted
    iRT, never from stored library times. A run with fewer than 100 anchors, or a residual SD above 10 iRT, contributes
    nothing.
  - Each run gives at most one time per precursor, the median of its identifications in iRT, and none from a double peak
    (gap over 3 iRT), a streak (span over 5), the first 4% of the run, outside the calibrated range, or a third of the
    run the fit does not fit well. The dataset's time is the median over its runs.
  - Against the stored time: a missing time is filled; within 7 iRT it is confirmed (the first confirmation stores the
    mean); beyond 12 iRT the stored time is kept but challenged, and a second strong disagreement replaces it; between 7
    and 12, nothing changes. A dataset that disagrees with more than 40% of the measured times it overlaps only confirms.
  - Pass one `MslRunObservations` per raw file of confident targets only (no decoys, contaminants or match-between-runs
    times), and feed each dataset once: the library does not record where a time came from. Precursors match by exact
    full sequence and charge; decoy entries are never updated.
  - A target whose measured time is in run minutes is refused before anything is predicted or written. If a predictor
    throws, nothing is written.
- **Libraries written by these two calls carry retention-time statuses (#1589, #1590)**, in #1582's reserved bits, so
  `.msl` stays format version 3. 1.0.598 and later read them; older readers ignore them.

## Performance

- **`TargetDecoyRescorer.Score` allocates about half as much, and gives the same scores (#1597).** At a tenth of a
  PXD022589 HF-X run it allocates 1.03 GB, against 2.09 GB. The new `ScoreSinglePrecision` takes `float[]` rows and
  widens each value exactly, so it gives bit for bit the scores of the same values as doubles. With only the allocation
  changes, MetaMorpheus's DIA result files were byte-identical.

## Fixes

- **A MassIVE listing that is cut short is now a failure, not a whole listing (#1609, a fix to #1574 in 1.0.598).** In
  1.0.598 and 1.0.599, `MassiveClient.GetDatasetFilesAsync`, and so `DownloadDatasetFilesAsync`, could return a listing
  with files missing and no exception, when MassIVE's FTP server went down during a `LIST` or refused a folder with
  550. A listing now needs its closing reply: no reply is an outage (`HttpRequestException`, retried), a 4xx reply is
  retried, and a 5xx reply is an `MzLibException`. An empty folder still lists as empty.
- **`QuantificationEngine` quantifies a run whose every match is ambiguous only in where its modifications sit
  (#1602).** `ValidateEngine` refused the empty peptide list before #1504's rows for those matches were built, so such a
  run returned `Success = false`, and a null list threw. An empty or null list is now refused only when no match is
  site-ambiguous with intensities. Found in review of MetaMorpheus #2973, whose TMT path reaches it.

Test, CI and internal:
- **#1584 and #1588** move DIA-NN's run-to-file matching and mzIdentML's native-ID and modification-location helpers into
  internal classes, for the Spectronaut and mzTab readers that follow. The readers answer as before.
- **#1611** drafts a TMT or iTRAQ deposit's SDRF as one row per file and channel, from a kit something states; the plex,
  fraction, technical replicate and channel sample are `not available`, so `SdrfIsobaricDesign` refuses the draft rather
  than read an invented design. Of 1,148 drafted deposits, 101 change.
- **#1620** gives the `build` job 75 minutes, not 45: two runs, master's among them, were cancelled at 45 with their
  tests still passing.

## Known issues

- **A loss keyed `DissociationType.MPD` no longer round-trips (#1182).** `Modification.ToString()`, and so
  `ProteinDbWriter`, writes it as `MPD:`, which now reads back as `IRMPD`. Nothing mzLib or MetaMorpheus ships uses MPD.
- **MGF native IDs after averaging, and read back from mzIdentML (#1613).** Every-n or DDA averaging of an MGF gives each
  averaged scan `index=<scan number>`, which names a different block (it threw before #1613). mzLib's mzIdentML reader
  turns `index=N` into scan N + 1, which is not the MGF's scan number when `SCANS` is set or a block was dropped. Join MGF
  results on `MsDataScan.NativeId`.
- **`UpdateRetentionTimesAndSave`'s length offsets and tiebreak are tied to Prosit 2025 (#1589; #1618 is open).** Use
  `FromKoina(new Prosit2025iRT40PTM())` as its predictor until #1618 lets the caller's predictor set them. It reads the
  whole library into memory, also when it was opened index-only, and writing in place over an index-only library is
  untested: write to a new path.
- **An `.msp` converted to `.msl` is labelled `Predicted`** (`MslLibraryEntry.FromLibrarySpectrum`), so a converted
  measured library run through `UpdateRetentionTimesAndSave` becomes `EmpiricalRefined`. Set `Source` to `Empirical`
  after converting.

  #2973's planned test can come with the bump). Its follow-up switches MGF mzIdentML output to MS:1000774 and `index=`
  IDs (#1613; MetaMorpheus #2981 wrote `scan=` while waiting); see Known issues before it does.
- **FlashLFQ:** takes #1607 through `FlashLfqEngine` at its next bump.
- **PXReprise and dataRepo:** the engine and datarepo move to this release together (PXReprise D84). #1590 is the
