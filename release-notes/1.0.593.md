# mzLib 1.0.593 — statistics, Gene Ontology on protein groups, and RNA quantification tables
**Source:** `1.0.592..1.0.593` (`c8ee03e5..2e31b676`, 26 PRs)
**Contributors:** @Alexander-Sol, @nbollis, @trishorts

Most of this release is new API, but four changes affect existing callers. **The package now ships
eight more DLLs**, and MetaMorpheus's installer check fails until they are listed (first item).
**Code that reads `SdrfSample.BiologicalReplicate`, `SdrfAssay.TechnicalReplicate` or
`SdrfAssay.Fraction` into an `int` stops compiling.** Code that imports both `EngineLayer` and
`Omics.Modifications` and names `IsobaricMassTag` becomes ambiguous. Code that catches `IOException`
or `TaskCanceledException` from `PrideArchiveClient` stops catching some failures. Everything else is
additive. MetaMorpheus master already builds and passes its tests against this code; mzLib's
`integration` job is green on `2e31b676`.

## Breaking changes

- **Eight new DLLs in the package (#1341, #1372)** — `StatisticalModels.dll` is a new mzLib
  assembly. `PdfPig` 0.1.16 (Apache-2.0, managed only) is a new package dependency. It brings
  seven assemblies: `UglyToad.PdfPig`, `.Core`, `.DocumentLayoutAnalysis`, `.Fonts`, `.Package`,
  `.Tokenization` and `.Tokens`. All eight land in every consumer's build output.
  MetaMorpheus's `Validate Installer Contents` job fails on any built DLL that
  `Product.wxs` does not install, so **MetaMorpheus's bump to 1.0.593 must add eight `Product.wxs`
  components**, or whitelist them. No file was removed from the nuspec, so nothing that installs
  today goes missing. The Anthropic SDK used by #1377 is **not** in the package. Its project,
  `SampleEvidenceModel`, is deliberately left out of `mzLib.nuspec`.
- **SDRF replicate and fraction numbers are `int?` (#1378)** — `SdrfSample.BiologicalReplicate`,
  `SdrfAssay.TechnicalReplicate` and `SdrfAssay.Fraction` can now be `null`, meaning "nobody
  established this". The builder writes `not available` for a null, or refuses it under
  `RequireSampleMetadata`, which is the default. The default value is still `1`, and `0` still
  throws. Code that assigns an `int` compiles unchanged. Code that reads one into an `int` does
  not, and binaries built against 1.0.592 must be rebuilt. `ISampleInfo` and `SpectraFileInfo` are
  untouched.
- **`IsobaricMassTag` and `IsobaricMassTagType` are now mzLib types in `Omics.Modifications` (#1375)**
  — they have the same names as MetaMorpheus's `EngineLayer` types. A file that imports both
  namespaces and names either type fails with `CS0104`. MetaMorpheus #2860 (merged) adds
  using-aliases in its four affected files. Any other consumer that imports both namespaces needs
  the same alias. See New for what the types do.
- **`PrideArchiveClient` reports every transport failure as `HttpRequestException` (#1350)** — this
  breaks nothing at compile time:
  - A connection dropped mid-download used to throw a bare `IOException`. It now throws
    `HttpRequestException`, with the `IOException` as its inner exception.
  - An `HttpClient.Timeout` waiting for headers used to throw `TaskCanceledException`. It now throws
    `HttpRequestException`.
  - A caller's own cancellation is still `OperationCanceledException`.
  - A failure opening or writing the local `.partial` file is still `IOException`, because it is
    the caller's disk, not an outage.
  - `StatusCode` is now set on every non-success response, so a 403 can be told from a 503 without
    parsing the message.
  - Download messages now name `'<file>' from <host>` instead of the full URL, so a
    reviewer-token query string can never reach a log.
  - **A `catch (IOException)` or `catch (TaskCanceledException)` around a download no longer sees
    these failures.** Catch `HttpRequestException` instead.

## Changed answers

- **Terminal ProForma modifications read back on their own residue (#1376)** —
  `ProFormaConverter.ToModificationDictionary` used to resolve a terminal descriptor to the first
  loaded modification allowed at that terminus, whatever its residue. Of 121 terminus-restricted
  modifications written and read back, 41 came back on a **different** residue. Examples:
  `Myristoyl on G` came back as `Myristoyl on C`, and N-terminal `Dimethyl on P` as
  `N6,2'-O-dimethyladenosine on A`. Masses were always right, which is why nothing numeric
  noticed. Now 0 of the 121 change residue. A terminal descriptor that fits no modification on its
  residue throws `MzLibException`, as an interior one already did. The 14 that still resolve to
  another entry on the same residue share one accession, which cannot tell them apart.
- **Four shipped modifications now cite Unimod (#1328)** — `GG (Ubiquitination Site)` (UNIMOD:121),
  `Myristoylation` on G and on C/K (UNIMOD:45), and `EQIGG` (UNIMOD:846). These modifications now:
  - are written to ProForma as `[UNIMOD:n]` instead of by name;
  - carry the accession in written protein XML databases and in SDRF `AC=` cells;
  - can be sent to Koina models.

  Without an accession, a downstream pipeline keyed on Unimod silently dropped every ubiquitination
  site. Masses are unchanged.
- **`AllProteinGroups.tsv` and per-file `*_ProteinGroups.tsv` are recognised (#1365)** —
  `FileReader` used to recognise only `*QuantifiedProteinGroups.tsv`. It threw
  `Tsv file type not supported` on the other names MetaMorpheus writes: without label-free
  quantification, and for individual files. Any `*ProteinGroups.tsv` now reads as
  `MetaMorpheusQuantifiedProteinGroups`. No enum member is added, and the name written back out is
  unchanged.
- **Reading a plain `.mzid` streams from disk, and every read fault names the file (#1362)** —
  - A 20 MB `.mzid` allocated 92.5 MB to read and now allocates 5.2 MB, with the same records.
    `.mzid.gz` is still buffered, because a gzip stream cannot be re-read.
  - An `IOException` reading a file that exists, such as a sharing violation or a truncated file,
    is now an `MzLibException` that names the file.
  - A missing file still throws `FileNotFoundException`.
  - A modification with no `location` is now reported as `modification has no location`.

## New

- **RNA quantification tables, and `SupportedFileType` goes from 36 members to 38 (#1388)** —
  MetaMorpheus's `All[Quantified]TranscriptGroups.tsv` and `AllQuantifiedOligos.tsv` load through
  `FileReader` as `TranscriptGroupFromTsvFile` and `QuantifiedOligoFile`. They have the same columns
  as the protein-group and quantified-peptide tables, including parsed RNA modification occupancy.
  The two members, `MetaMorpheusQuantifiedTranscriptGroups` and `FlashLFQQuantifiedOligo`, are
  appended, so existing integer values are unchanged. A `switch` with a throwing default will throw
  on them.
- **Statistics, in a new `StatisticalModels` assembly (#1341, #1357)** — these fit one design
  against many features, using MathNet.Numerics, which mzLib already shipped, and no R:
  - **`LinearModel.Fit`:** per-feature least squares, omitting missing values rather than imputing
    them. Each feature reports why it could not be fitted.
  - **`MultipleTesting.BenjaminiHochberg`.**
  - **`RandomEffectsMeta.Pool`:** DerSimonian–Laird pooling.
  - **`EmpiricalBayes`:** limma-style variance moderation, with an optional intensity trend.
  - **Agreement:** each matches limma 3.68.5 or metafor 5.2.1 to within 1e-8 relative on reference
    fixtures.
  - **Limitation:** `EmpiricalBayes` is limma's **legacy** estimator (`eBayes(legacy = TRUE)`).
    Limma's current default differs whenever residual df differ between features, which per-feature
    missing values cause. `ModeratedTest.ResidualDfDiffer` says when a result is on such input.
  - **Naming:** the namespace is `StatisticalModels`, not `Statistics`, so it does not hide
    MathNet's `Statistics` class.
- **Gene Ontology on protein groups (#1353, #1366)** — the annotator puts GO terms on protein groups
  without picking a leading protein:
  - **Graph:** `GeneOntologyGraph` reads go.obo and walks `is_a` and `part_of` only.
    `Loaders.LoadGeneOntology` and `UpdateGeneOntology` fetch it. The full release, 48,340 terms,
    loads in about 0.3 s.
  - **Rows:** `GoGroupAnnotator` writes one row per (group, term) that any member holds, directly or
    through an ancestor. Each row records which members carry the term and with what evidence.
    Every non-decoy group gets at least one row, and `annotation_status` says why one has no terms.
  - **Categories:** `GoCategoryMap` applies a caller's own term-to-category map. mzLib ships no
    vocabulary.
  - **Stored tables:** `ProteinGroupFromTsv.ToGoAnnotationGroups()` reads a stored MetaMorpheus
    table straight in. It skips decoys and annotates a group MetaMorpheus wrote twice only once.
  - **Entrapment:** `ProteinDbLoader.IsEntrapmentAccession` makes the loaders' entrapment rule
    public, and the `entrapment_members` column labels entrapment members.
  - **Isoforms:** an isoform in the searched database now inherits its UniProt entry's GO. On
    PXD007188 that took 0 inherited rows to 338.
  - **Real data:** a PXD036557 table (715 target groups) produced 87,513 rows in about 20 s.
- **Isobaric kits with every channel named (#1375)** — `IsobaricMassTag` gives the channel labels and
  reporter-ion m/z for TMT6/10/11, TMTpro 16/18, iTRAQ4/8 and DiLeu4/12.
  - The m/z values are derived from `TMT.txt`'s diagnostic ions plus a proton, and checked against
    the published values.
  - Lookup matches whole names, so `TMT10plex` no longer resolves as MetaMorpheus's `Contains`
    chain allowed.
  - `TMT16` is new.
  - Label spellings are MetaMorpheus's current ones.
- **Median polish and max roll-ups (#1399)** — `MedianPolishRollUp` and `MaxRollUp` are roll-up
  strategies for the Quantification engine. With them, the engine reproduces FlashLFQ's peptide and
  protein intensities exactly on the K562 test files: all 708 peptide values, with and without
  match-between-runs.
  - FlashLFQ's median polish code now lives in Quantification, and `FlashLFQ.dll` references
    `Quantification.dll`.
  - **FlashLFQ's results are unchanged**, and `FlashLfqResults.MedianPolish` remains as a
    pass-through.
  - Unlike FlashLFQ, which reports NaN, the roll-up gives a sample it cannot quantify 0.
- **A label-free experimental design from an SDRF (#1363)** — `SdrfLabelFreeDesign.Read` turns an SDRF
  into MetaMorpheus's `ExperimentalDesign.tsv`, or refuses it and lists every reason at once.
  MetaMorpheus skips quantification on an invalid design with only a warning, so refusing beats
  repairing. It runs every check MetaMorpheus's validator runs. It ranks study-wide biological
  replicate numbers (control 1–3, treated 4–6) within each condition and reports the mapping.
- **Europe PMC (#1373)** — `EuropePmcClient` finds a PRIDE project's paper and downloads its JATS full
  text and supplementary zip. A file already on disk is reused, so a download folder acts as a cache.
  It follows #1350's error contract.
- **SDRF drafting from file names, papers and supplements (#1351, #1354, #1355, #1372, #1374, #1377,
  #1397)** — these PRs read designs out of raw-file names and supplementary tables (xlsx, docx, csv,
  PDF), and restrict an SDRF to the files one search read. They also add an opt-in model reader in
  the separate, unpacked `SampleEvidenceModel` project. **All of it is `internal`**, so none of it is
  callable from the NuGet package yet. It is listed here because it is why `PdfPig` is now a
  dependency.

## Fixes

- **Linux builds include `PepXML.dll` (#1364)** — the folder and project were spelled `pepXML` while
  every reference said `PepXML`. On a case-sensitive file system, `Proteomics` built without it and
  only warned. The assembly name, namespace and package contents are unchanged.

## Test-only and cleanup

- **A skipped live PSI-MOD test no longer breaks ~220 later tests (#1394)** — it restores
  `Console.Out` on the skip path. This is test-only.
- **Documentation (#1361, #1395)** — #1361 records the 1.0.592 TOML break in `release-notes/1.0.592.md`
  to match the published page. #1395 merges a duplicated doc summary. Neither changes code.

## Downstream

- **MetaMorpheus** needs eight `Product.wxs` components (first breaking item) in its bump to 1.0.593,
  or `Validate Installer Contents` fails. Its source is ready: #2860 aliased `IsobaricMassTag`, and
  mzLib's `integration` job, which runs MetaMorpheus master's suite, is green on this release's
  commit. MetaMorpheus #2816 (SDRF output) can pass `null` replicate and fraction numbers once it
  takes this release.
- **pyMzLib, mzLibRust and mzLibR** pin `SupportedFileType` counts. Those move from 36 to 38.
- **FlashLFQ and ProteaseGuru** need a version bump only, as far as this changeset shows. The eight
  new DLLs reach their outputs too.
