# mzLib 1.0.601 — DIA precursors in the differential statistics, a corrected pooled set test, the OpeRATOR, IMPa and SmE glycoproteases, PRIDE zip entries without the zip, and `.msp` times that keep their scale
**Source:** `1.0.600..1.0.601` (`43d44021b..12de79d44`, 10 PRs)
**Contributors:** @nbollis, @pcruzparri, @trishorts

**MetaMorpheus cannot take this release with a pin change alone.** The package now depends on System.IO.Hashing
10.0.10 (#1617). `System.IO.Hashing.dll` is not part of the .NET 10 shared framework, so it lands in MetaMorpheus's GUI
output, and MetaMorpheus's installer lists its DLLs by hand: `validate_installer_contents` fails until `Product.wxs` gains
a component beside FluentFTP's (added for 1.0.598 by MetaMorpheus #2966). WiX needs the file in the build output, so the
component cannot go in before the bump: the order is release first, then one MetaMorpheus PR that bumps mzLib and adds
it. Otherwise a pin change builds and passes: mzLib's `integration` job built MetaMorpheus master (`425a3f6e4`) against
mzLib master at `12de79d44` (run 45453705348), and 4,218 of 4,221 tests passed, 3 were skipped, none failed. That job
builds the installer but does not compare its DLLs, so it stays green.

**The set test's pooled rows can now be acted on.** 1.0.600's notes said its pooled standard error "can be far too small
until #1616, which is **not** in this release". This release carries #1616. Nothing in mzLib, MetaMorpheus or PXReprise
calls `SetPooling.Run`, and the share model (S4b) and the set test's output files (S5) are still not in this release.

Answers change for existing callers in these places:
- the set test's pooled rows, and the family columns beside them (#1616);
- `n_peptides` on isobaric differential rows (#1622), and a normalization setting the runner does not know, now refused
  (#1622);
- `.msp` times read from `RT=`, which now convert to `.msl` as run minutes, not iRT, and `.msp` files written from iRT
  times, which now say `iRT=` (#1625);
- the built-in protease list, which gains six entries in its middle (#1600), and StcE-trypsin with both cleavage
  corrections on (#1601);
- the de novo mapping summary, which gains 3 columns, or 15 with a host (#1615);
- `ms2pip_CID_TMT`, which now predicts a sequence with no N-terminal label (#1568).

## Breaking changes

- **System.IO.Hashing 10.0.10 is a new package dependency (#1617).** Both nuspec groups declare it, and
  `UsefulProteomicsDatabases` references it. Only the new zip-entry fetch uses it, for CRC-32, but restore brings
  `System.IO.Hashing.dll` into every consumer's build output. It is Microsoft's, MIT-licensed, at the runtime's own patch
  level, and its `net10.0` group has no dependencies of its own, so it is one DLL. Neither `Microsoft.NETCore.App` nor
  `Microsoft.WindowsDesktop.App` 10.0.10 ships it. **An installer that lists its DLLs by name must add it;** see
  **Downstream**.
- **Rebuild against this release if you construct or deconstruct these records, or construct a `CleavageRequirement`
  (#1622, #1600).** Each gained trailing optional parameters, and no constructor of the old shape was kept:
  - `PeptideRunValues` and `Observation`: `int? Charge = null` (#1622);
  - `NormalizationResult` and `DifferentialNormalizationInfo`: `int? DeclaredGroups = null,
    IReadOnlyList<string>? DeclaredGroupsAbsent = null` (#1622);
  - `CleavageRequirement`: `bool isForbidden = false` (#1600).

  Source that constructs them compiles unchanged. The four records are positional, so each `Deconstruct` gained the same
  parameters, and source that deconstructs one into the old number of variables does not compile. A binary built against
  1.0.600 that constructs or deconstructs one throws `MissingMethodException` until it is rebuilt. Reading their
  properties is unaffected. MetaMorpheus, ProteaseGuru and PXReprise construct none of them; mzLib builds
  `CleavageRequirement`s only from `proteases.tsv`.
- **`SetPoolingName.PooledStandardErrorZero` is gone, and `PooledModel` has a new value (#1616).**
  - 1.0.600 wrote `pooled_standard_error_zero` as a pooled row's `not_run` reason when every dataset gave the same
    estimate. Such a row is now tested. The only `not_run` reason left is `PooledNotComputable`,
    `pooled_not_computable`: datasets whose standard errors are below about 1e-154 or above about 1e154 log2, where the
    weights 1/se² cannot be formed in double precision. Source that names the old constant does not compile.
  - `PooledModel` goes from `random_effects_hartung_knapp` to `random_effects_hartung_knapp_adhoc`. A `const` is copied
    into the code that uses it, so a binary built against 1.0.600 compares against the old string, and matches no pooled
    row, until it is rebuilt. `PooledDfMethod` stays `hartung_knapp` (k − 1).
- **What does not break:** no default changed; `DifferentialResults.tsv` keeps its 57 columns in the same order; a run
  the runner still accepts keeps its `analysis_id`; `DigestionParams` is unchanged, so MetaMorpheus's settings-save test
  stays green; `MslRetentionTimeUpdateOptions` keeps its constructor (#1624).

## Changed answers

- **The set test's pooled standard error never falls below DerSimonian–Laird's (#1616).** `SetPooling.Run` now pools
  with `RandomEffectsInference.HartungKnappAdHoc`: the larger of the Hartung–Knapp and the DerSimonian–Laird standard
  error, on the same t(k − 1). This is metafor's `test = "adhoc"` (Knapp and Hartung 2003), as QuantProject ruled on
  2026-11-19.
  - **1.0.600's worked example:** two datasets at 1.000 and 1.001 log2, each with se 0.3 on 10 df, pooled to se 0.0005
    and a one-sided p of 0.00016. They now pool to se 0.212 and p 0.067, so the row is not supported. Each dataset alone
    has p = 0.004.
  - **It moves every pooled row where the correction binds, and the family columns those rows share.** On the PR's R
    scenario, HD's pooled se goes from 0.024 to 0.062 (adjusted p 0.079), so HD is no longer supported and R falls from 3
    to 2. HA's se goes from 0.0954 to 0.1135 and it stays supported. HC is not pooled and keeps p = 0.01096, but its
    family-adjusted p goes from 0.0311 to 0.0329. The Benjamini–Bogomolov level falls from 0.025 to 0.0167.
  - **Pools whose datasets give exactly one estimate are now tested,** on the DerSimonian–Laird standard error. In 1.0.600
    they were `not_run`.
  - **The cost is power when only two datasets are pooled.** Over 4,000 simulated pools per setting (true effect 0.5 log2,
    τ = 0), power falls from 0.39 to 0.02 at k = 2, from 0.77 to 0.67 at k = 3, and from 0.97 to 0.96 at k = 5. Plain
    Hartung–Knapp, where it was narrower than DerSimonian–Laird, covered only 79–88% of a nominal 90%; corrected coverage
    is 0.91 to 1.00. Each dataset's own row, `n_datasets_agree` and the "supported in at least 2" p are still reported.
  - **What does not change:** `RandomEffectsMeta.Pool`'s default (`Normal`) and its `HartungKnapp` option, the pooled
    estimate and τ² (DerSimonian–Laird's), the verdict rules, and every unpooled row's own estimate, standard error and p.
- **An `.msp` time read from `RT=` now converts to `.msl` as minutes in one run, not as iRT (#1625).** MetaMorpheus
  writes every library time as `RT=`, in run minutes, and 1.0.600 stored every converted time as iRT. The new
  `LibrarySpectrum.RetentionTimeIsIrt` (`bool?`) carries the scale: the `.msp` reader sets it from the key it read, and
  `MslLibraryEntry.ToLibrarySpectrum` from `RtIsCalibrated`. So `MslConverter.FromMspFile` stores `RT=12.5` as 12.5 run
  minutes and `iRT=33.25` as iRT, and an `.msl` entry in run minutes survives a round trip through `LibrarySpectrum`.
  - **To put a converted `.msp` on iRT, call `MslPredictedRetentionTimes.Assign(..., ReplaceAll)` right after
    converting.** `ReplaceAll` resets every time and its label, so a library built that way is the same on 1.0.600 and
    1.0.601. `FillMissing` does not touch a converted `.msp`, whose minutes are not NaN.
  - A converted library's minutes are now labelled minutes everywhere. `UpdateRetentionTimesAndSave` treats a run-minute
    time with no status as unmeasured and replaces it with the first accepted iRT. A DIA search that refuses run-minute
    libraries (MetaMorpheus #2984, open) now refuses a raw conversion, where 1.0.600 would have let it search minutes as
    iRT.
  - **`.msp` files predicted by an earlier mzLib carry iRT under `RT=`.** Nothing in them says they were predicted, so
    they now convert as run minutes. Regenerate them, or convert and run `Assign` with `ReplaceAll`.
  - **What does not change:** a `LibrarySpectrum` built in code has no scale and converts as iRT, as before (see **Known
    issues**). pDeep and ms2pip text libraries convert as iRT. The `.msl` format is unchanged.
- **An `.msp` written from iRT times now says `iRT=`, where it said `RT=` (#1625).** `LibrarySpectrum.ToString` writes
  `iRT=` when `RetentionTimeIsIrt` is true. `FragmentIntensityModel.GenerateLibrarySpectraFromPredictions` declares every
  time it is given to be iRT, so a Koina-predicted `.msp` says `iRT=30.5` and still converts as iRT; do not pass it
  run-aligned minutes, whatever its `alignedRetentionTimes` parameter suggests. Spectra read from an `.msl` in iRT, or
  from an `iRT=` line, are written back with `iRT=`. mzLib has read `iRT=` before `RT=` since #914, so every value reads
  back unchanged; a tool that looks only for `RT=` finds no time on those lines.
- **`n_peptides` on a differential row now counts distinct peptides, as documented (#1622, a fix to #1591 in
  1.0.600).** 1.0.600 wrote the number of model levels. A TMT level is one peptide ion in one plex run, so isobaric rows
  fall wherever a peptide was seen at more than one charge or in more than one plex run: the two-plex fixture goes from 8
  to 4. The model choice is still made by the number of levels, so no estimate, standard error or p changes. Label-free
  rows are unchanged. The `analysis_id` and `method_version` (`diff-1.0`) do not change either, so record the mzLib
  version beside an isobaric table if you compare across the bump.
- **A normalization setting the runner does not know is refused (#1622).** In 1.0.600 every setting except `none` ran the
  default, so a typo ran silently. `DifferentialAnalysis.Run` now throws `ArgumentException` naming it. Accepted:
  `shared_peptide_median`, `none` and `background_set:<name>` for a label-free table; `shared_peptide_median` (its
  channel median, as before), `global_channel_median` and `none` for an isobaric one. So `global_channel_median` on a
  label-free table, and `shared_peptide_median_half` on either, now fail. A row with the new `QuantStyle = "dia"` writes
  `quant_basis` and `n_mbr_values` empty. **What does not change:** the default, and every accepted run's numbers and id.
- **Six digestion agents join the built-in list, which grows from 24 to 30 (#1600):** `OpeRATOR`, `IMPa`, `SmE`, and
  `OpeRATOR-trypsin|P`, `IMPa-trypsin|P` and `SmE-trypsin|P`.
  - They sit after `StcE-trypsin`, so `CNBr_old`, `CNBr_N`, `ProAlanase` and `subtilisin|P` move six places down in any
    list built from `ProteaseDictionary.Dictionary`, MetaMorpheus's and ProteaseGuru's pickers among them. Finding a
    protease by name is unaffected; a stored position is not.
  - A custom protease named like one of the six is now skipped by `LoadAndMergeCustomProteases`, listed in `Skipped`,
    and the built-in is used.
  - **With `RespectCleavagePromotingModifications` off, the default, they cut by sequence alone:** OpeRATOR and SmE
    before every S and T, IMPa before every S and T not after a D. On `GADSATKSG`, OpeRATOR gives `GAD`, `SA`, `TK`,
    `SG`. With the flag on and no O-glycan possible, they never cut.
  - **What does not change:** every existing entry. On 948 human proteins, every existing protease and flag combination
    gives byte-identical peptidoforms to 1.0.600, except the next item.
- **StcE-trypsin with both cleavage corrections on no longer lets trypsin cut after a lysine whose modification blocks it
  (#1601, a fix to #1510 in 1.0.598).** This needs `RespectCleavageBlockingModifications` and
  `RespectCleavagePromotingModifications` both on, at a K or R that StcE's motif also spans. Trypsin's `K|` counted as the
  cut there whatever the lysine carried; now a motif that names P1 cannot cut when P1 carries a blocking modification.
  - On `GTKTAAR` with acetyl-K variable, 1.0.600 gave `GTK[acetyl]` even when nothing could glycosylate Thr2, and lost
    the uncut `GTK[acetyl]TAAR`. Now `GTK[acetyl]` comes out only as `GT[O-glycan]K[acetyl]`, and `GTK[acetyl]TAAR` is
    kept.
  - On 948 human proteins (O-glycans on S and T and acetyl-K variable, 2 missed cleavages, length 5–40): 1,960,220
    peptidoforms become 1,964,044, and 320 proteins change; 6,477 that end at such a lysine are gone, 10,301 read-throughs
    come in, and 9,690 report fewer missed cleavages.
  - Only a caller that sets both flags with StcE-trypsin sees it. No MetaMorpheus window sets the promoting flag yet
    (MetaMorpheus #2985 is open); a hand-edited `.toml` can. `CleavageBlockingPolicy.Blocks`, which GPTMD calls, is
    unchanged.
- **The de novo mapping summary gains columns (#1615).** `DeNovoMappingResultFile` writes 21 fixed columns where it wrote
  18 (`PeptideRetentionTimeErrors`, `PeptidePredictionScores`, `UniqueDecoyPeptidesMapped`), and 33 when any result has
  a host. The per-file counts now start at column 22, or 34, instead of 19. A reader by name keeps working. **mzLib
  1.0.599 and 1.0.600 read a new summary's extra integer columns as files:** read new summaries with this release. This
  release reads an old summary; the new lists come back empty and the new counts -1. Every existing field keeps its
  value, list order included.
- **`ms2pip_CID_TMT` now predicts a sequence with no N-terminal label (#1568).** It refused any sequence that did not
  start with a TMT6plex, TMTpro, iTRAQ 4-plex or 8-plex label; Koina's model does not need one. `PEPTIDEK` at charge 2 now
  gets a prediction under every handling mode. **The label still sets the m/z:** the intensities are identical, but the
  bare sequence's b1 is 98.060 against 327.223 with TMT6plex, so put the label on the sequence for TMT or iTRAQ data.
  Under `UsePrimarySequence` a labelled input loses its label and is predicted at unlabelled m/z, where 1.0.600 returned
  null. `Prosit2020IntensityTMT` and `Prosit2020iRTTMT` still require the label.

## New

- **DIA precursors go through the differential statistics: `DiaObservations.Build` and `DiaPrecursorRun` (#1623), and
  precursor rows in the runner's table (#1622).** `Build` takes the design's runs, every precursor in every run as an
  engine-neutral `DiaPrecursorRun` (file name without extension, sequences, charge, the producer's protein groups, the
  quantity and its `PrecursorQuantityKind`, run and global q-values, and decoy, entrapment and contaminant flags), and
  returns an `ObservationTable` for a request with `QuantStyle = "dia"`.
  - A precursor passes in a run when both q-values are at or below 0.01. A passing `Value` is quantified, a passing
    `BelowFloor` or `NotLooked` is identified without a value, and anything else is not detected. No cell is ever 0.
  - One row per precursor: charges are never summed. `PeptideRunValues` takes an optional `Charge`, and each row is the
    model level `{FullSequence}/{Charge}`, as a TMT ion already is. A table without charges is byte-identical to before.
  - Decoy, entrapment and contaminant precursors never enter. Technical replicates are averaged on the log scale;
    fractions are refused, as are duplicates, disagreeing groups, values that are not finite and above 0, and a run that
    reports nothing while another run of its sample does.
  - On a 20-group test with 10 groups 1 log2 higher, every row fits with `n_peptides` 2 from three precursors, and the
    effects are within 0.1 of 0 and 1. 29 tests; 14 planted mutants, each caught.
  - **Not in this release:** the mappings from `DiaPrecursorFromTsv` (MetaMorpheus's `AllDiaPrecursors.tsv`) and from
    `DiaNnPrecursor` (DIA-NN's report). Until then a caller builds its own `DiaPrecursorRun`s.
- **`background_set:<name>` normalizes on protein groups the caller declares unchanged (#1622),** such as non-specific
  binders, spike-ins or a mixture's constant species. Set `Normalization = "background_set:human"` and list the groups in
  the new `DifferentialSettings.BackgroundSetGroups`, named as the table names them. A peptide counts only if every group
  it maps to is declared. The set's sha256 enters the `analysis_id`, and the report names the set and how many groups
  were absent. On a mixture of 20 unchanged groups beside 40 that double, the shared-peptide median reads the unchanged
  groups at about −1; with them declared, they read 0 and the changing ones +1, each within 0.05. Label-free only for now.
- **`RandomEffectsInference.HartungKnappAdHoc` (#1616)** makes the correction available to any caller of
  `RandomEffectsMeta.Pool`. It is added after `Normal` and `HartungKnapp`, refuses a single study, and matches metafor's
  `rma(method = "DL", test = "adhoc")` on 10 cases at 95% and 90%.
- **OpeRATOR, IMPa and SmE, and a glycan that prevents a cut (#1600).** These are the O-glycoproteases #1510 left out.
  OpeRATOR and SmE are `|T,|S` with `P1':O-glycan`. IMPa is `[D]|T,[D]|S` with `P1':O-glycan;P1:!O-glycan`: it does not
  cut after D, or between two adjacent glycosites. The new `CleavageRequirement.IsForbidden` is read from a `!`, and a
  custom protease file may use it. On `GASTAAA` with glycans possible at S3 and T4, SmE gives `GA`, `GAS`, `GASTAAA`, `S`,
  `STAAA` and `TAAA`, and IMPa the same without the lone `S`. Not encoded: OpeRATOR's refusal of the Tn antigen and core
  2, and IMPa's slower cuts after Ile and Arg.
- **`DigestionProduct.GetCleavageConditions(agent, initiatorMethionineRetained = false)` (#1601)** reports the glycans a
  product's ends need, or must not carry, if the agent cut them there, as `(OneBasedResidue, CleavageRequirement)` pairs
  keyed by the parent's residue. Only ends that are cuts count, and a condition counts only when every motif cutting at
  that bond imposes it, so trypsin's `K|` in StcE-trypsin leaves none. IMPa's `TGGG` from `GGGATGGG` needs a glycan on T5
  and must have none on A4. Helpers: `DigestionAgent.MotifsCuttingAfter`, `DigestionProduct.IsCutBefore` and
  `IsCutAfter`, which `CleavageBlockingPolicy` now shares.
- **The de novo mapper tells host-ambiguous hits from hits only the database explains (#1615).** Set
  `DeNovoMappingParameters.HostProteins` (default null): the host's targets are digested once, and
  `DeNovoPrediction.IsHostShared` flags each prediction the host explains. Each result gains unambiguous counts, score
  lists and retention-time errors beside the totals, and one value per peptide (median error, median score), so a short
  peptide predicted hundreds of times counts once in a KS or mean test. On viral spike-ins in human saliva, 113 of the 139
  predictions behind false-positive viral databases are peptides human proteins also produce; for the true viruses, 1 of
  62. Calibration is unchanged.
- **List a zip in a PRIDE project, and fetch the entries you pick, without downloading the zip (#1617).**
  - `PrideArchiveClient.GetZipEntriesAsync(zipFile)` returns every entry (`FullName`, `Length`, `CompressedLength`,
    `Crc32`, `CompressionMethod`, `IsEncrypted`, `CanDownload` and the rest, named as `ZipArchiveEntry`'s are) from one
    HTTPS range request over the zip's last 65,577 bytes, and a second only when the directory starts before them.
    PXD009815's 22.8 GB ZIP64 zip (41 entries) and its 25 MB MaxQuant zip each listed from the one request.
  - `DownloadZipEntriesAsync(zipFile, destinationDirectory, selector, overwrite = true)` writes each picked entry at its
    path below the destination: two requests per entry, inflated into a `.partial` moved into place only when its CRC-32
    and size match. `mqpar.xml` and `parameters.txt` from the MaxQuant zip came to 4 KB.
  - Every read after the first carries `If-Range`, so a zip PRIDE rewrites mid-read is an `MzLibException`, never a mix.
    Failures keep the client's contract (`HttpRequestException` for unavailability, `MzLibException` for broken bytes or
    a damaged zip, `NotSupportedException` for a split zip, encryption, Deflate64 and other methods, `ArgumentException`
    for a path that leaves the destination). HTTPS only; an entry is never resumed. The zip parser knows no HTTP, so the
    MassIVE client can use it later.
- **The retention-time update's Prosit 2025 numbers become options (#1624, closing #1618).** `MslRetentionTimeUpdateOptions`
  gains `PredictionOffsetByLength` (default `Prosit2025PredictionOffsetByLength`: −3.54, 0.35, 2.39, 4.90 and 4.91 for
  7–10 to 26–30 residues), `TiebreakFarFromPrediction` (15 iRT) and `TiebreakNearPrediction` (5), each checked before
  anything runs. The defaults give 1.0.600's answers. With Prosit 2025, leave them alone; with another predictor, measure
  its offsets and set all three. Two option sets with equal offsets in different lists are no longer `Equals`.

## Performance

- **`DeNovoMapper.MapDatabase` is 5 to 10 times faster and gives the same results (#1615).** Plain, fully specific
  digestion of a `Protein` is now walked as spans of the I/L-normalized sequence, with no `PeptideWithSetModifications`
  per peptide; everything else (semi- and non-specific, top-down, glyco filters, an active blocking policy, subclasses)
  falls back to `Digest`. On 10,000 viral FASTAs (1.1 M proteins with decoys), 42,123 Casanovo predictions and human
  UniProt as host, trypsin, 24 threads:

  | | before | after |
  |---|---:|---:|
  | one database at a time, `MaxThreads` 1 | 6.9 ms | 1.2 ms |
  | databases in parallel, one thread each | 1.56 ms | 0.16 ms |
  | host marking, 52k human proteins | 4.0 s | 0.55 s |

  All 10,000 results were identical to the old path in every field, list order included, and so was the set of
  host-shared sequences. The tests compare the walk with `Digest` under 10 digestion settings on 1,200 random proteins,
  and five bugs planted in review each turned the suite red.

## Fixes

- **`UpdateRetentionTimesAndSave` no longer judges another predictor by Prosit 2025's numbers (#1624).** This was
  1.0.600's known issue; see **New**. It still reads the whole library into memory, also when it was opened index-only,
  so write to a new path.
- **A TMT statistics report now says what normalization did (#1622).** Every isobaric `StatisticalReport.md` said
  "normalization `global_channel_median` over 0 reference peptides". It now describes MSstatsTMT's global channel-median
  normalization. Only the text changes.
- **One pool whose numbers cannot be formed no longer stops the set test, and `RandomEffectsMeta.Pool` no longer throws
  on one (#1616).** At dataset standard errors of 1e-160, `Pool` threw `ArithmeticException` with every inference; it now
  returns a NaN estimate. Near 1e-154 the row is `not_run`, `pooled_not_computable`, and the other parts pool as usual.

## Known issues

- **A `LibrarySpectrum` built in code still converts its time as iRT (#1625).** Spectra made from search results
  (MetaMorpheus's `SpectralMatch.ToLibrarySpectrum`, mzLib's `PsmFromTsv.ToLibrarySpectrum`) carry run minutes with no
  label: set `RetentionTimeIsIrt = false` before converting them. An `.msp` converted to `.msl` is still labelled
  `Predicted`, with dissociation type `Unknown`: set `Source` and the measured type after converting.
- **One degenerate pool can still stop `SetPooling.Run` (#1616).** Two `attenuated_down` datasets with standard errors
  near 1.5e-154 and an mRNA mean of −10 pass the guard, their weighted mRNA mean overflows to −∞, and `SetVerdict.Test`
  throws. Raised after the merge; only standard errors near 1e-154 reach it.
- **The set tests read a precursor table's rows as peptides, and normalization counts precursors (#1622).** Do not pass a
  `DiaObservations` table to the set test. On a precursor table the normalization floor of 100 is 100 precursors. A
  follow-up gives each kind of table its own unit. `QuantStyle = "dia"` is not refused on an isobaric table, and
  `QuantStyle` does not enter the `analysis_id`.
- **`DiaObservations.Build` checks the kind and quantity of every target record, including one that fails the q-values
  (#1623).** A producer that writes 0 for a precursor it did not quantify fails the whole build: map such a value to NaN
  with a kind that has no value.
- **OpeRATOR, IMPa and SmE appear in every MetaMorpheus protease picker before any window can turn their glycan rule on
  (#1600).** MetaMorpheus #2985, which adds that control, is open. In the Search, GPTMD, Calibrate and Crosslink windows
  they cut by sequence alone. None of the six has a PSI-MS accession, so `SdrfBuilder` writes them as `NT=` alone and
  MetaMorpheus's mzIdentML writes an empty accession.
- **Two zip entries can land on one file (#1617).** Entries that map to the same local path (`a/x.txt` and `a\x.txt`, or
  `X.txt` and `x.txt` on Windows and macOS) are both written there, the second over the first: pick one in the selector.
  Entry names are always read as UTF-8, so a non-ASCII name written without the zip's UTF-8 flag lists with U+FFFD in it.
- **Documentation only:** `DigestionAgent.MotifsCuttingAfter` sits between `GetDigestionSiteIndices` and that method's
  doc comment, so `GetDigestionSiteIndices` has lost its summary (#1601).
