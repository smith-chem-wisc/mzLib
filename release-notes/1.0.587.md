# mzLib 1.0.587 — quantification becomes usable end to end

**Source:** `1.0.586..1.0.587` (12 PRs)
**Contributors:** @acesnik, @trishorts

Two things in this release change what existing callers see without them changing any code: **`QuantifiedPeaks.tsv` gains two columns**, and **`QuantificationEngine` now excludes ambiguous spectral matches**. Both are the first two items. Three public types and one property were also removed from the `Quantification` project; see the fourth item.

The headline is that `Quantification` is now a working pipeline rather than an engine with both ends missing. Before this release `QuantificationEngine.Run()` threw on any default configuration, and nothing wrote results anywhere. It now ingests, computes, delivers onto the entities and writes three tables.

## Changes

- **`QuantifiedPeaks.tsv` gains two columns (#1180)** — `Peak FWHM` and `Peak FWHM Status`, inserted after the retention-time columns and before the apex m/z. **Anything parsing that file by column index will read the wrong field from this release on**; parse by header name. FWHM is measured on the apex charge state alone, interpolated between the bracketing scans rather than quantised to the MS1 cycle. A peak whose trace ends while still above half maximum reports `Censored` rather than a number, which is expected for wide or co-eluting peaks rather than a failure. `PeakWidthSummary.Summarize` aggregates it per file, optionally in equal-count retention-time bins. Closes MetaMorpheus #1624, open since 2019.

- **Ambiguous spectral matches are excluded from quantification (#1210)** — `GetPsmToPeptideMap` previously took the first biopolymer a match identified, under a comment reading "Assumes unambiguous mapping". A match identifying several was therefore attributed to whichever came first: a plausible intensity, recorded against a peptide that may not be the one measured. Such matches are now dropped, and the count is reported as `QuantificationResults.AmbiguousSpectralMatchesExcluded` and echoed in `Summary`, so a result set smaller than the search has a stated cause. **If you quantify through mzLib directly you will see fewer matches used and different protein-level numbers.** MetaMorpheus already filtered at its own call site and is unaffected. Ambiguity is judged on *distinct* identifications, so a match naming one peptide once per protein it maps to still counts as unambiguous. This also removes a crash: the old `.First()` threw on a match carrying no identification at all.

- **Quantification results are delivered and written (#1193)** — `QuantificationEngine` computed a matrix and stopped; nothing populated `IBioPolymerGroup.IntensitiesBySample`, and `QuantificationWriter`'s three methods all threw `NotImplementedException` while their enabling flags defaulted to true — so `Run()` threw on any default configuration. The engine now writes final values back onto anything implementing the new `IHasSampleIntensities`, and the writer produces `RawQuantification.tsv`, `PeptideQuantification.tsv` and `ProteinGroupQuantification.tsv`. `OutputDirectory` is optional: left unset with writing enabled, the engine derives one from the spectral matches' own file paths and reports it back as `QuantificationResults.OutputDirectory`. Peptide-level intensities ride on the results object rather than on `PeptideWithSetModifications`, which is `[Serializable]` and serialized in bulk during indexing.

- **Sample collapsing split into two strategies; `SumCollapse` and `MeanCollapse` removed (#1194)** — collapsing hardcoded `Condition + "_" + BiologicalReplicate` and baked the aggregation into the same type. It is now `ICollapseStrategy` (which samples are combined) plus `IAggregationStrategy` (how), so fractions, technical replicates and biological replicates can each be collapsed independently. **`SumCollapse` and `MeanCollapse` no longer exist**; use `CollapseFractions`, `CollapseTechnicalReplicates`, `CollapseBiologicalReplicates` or `CollapseFractionsAndTechnicalReplicates` with `SumAggregation`, `MeanAggregation`, `MedianAggregation` or `MaxAggregation`. `QuantificationParameters` gains `CollapseStrategy` and `CollapseAggregationStrategy`.

- **Roll-up strategies collapsed onto one implementation, fixing a silent intensity inflation (#1211)** — `SumRollUp` and `MedianRollUp` were two copies of one loop, and the sum copy accumulated with `+=` into a buffer taken from `ArrayPool<double>.Shared`, which `Rent` does not zero. It returned its own buffers cleared, but `MedianAggregation` and the collapse strategies share that pool and return theirs uncleared — **so a sum could pick up another strategy's leftovers and report an inflated intensity, silently, with no error**. It needed a median or a collapse to have run first in the same process, which is why nothing caught it. Both now derive from an abstract `AggregatingRollUp` that writes every column before reading it. `SumRollUp.ArrayPool`, a public property exposing an implementation detail, is **removed**. `MedianRollUp` now treats a negative value as data rather than as missing; intensities are non-negative, so no existing result moves.

- **A peptide's protein groups no longer leak into other files' identifications (#1147)** — `FlashLFQResults` builds a `Peptide` from the first `Identification` carrying a given modified sequence, and `Peptide` held that identification's `HashSet` rather than a copy. Every later identification for the same sequence then wrote into it, **so protein groups leaked into identifications that never observed them — within a single run, not only across a merge**. Since `ChromatographicPeak.ToString()` builds its Protein Group and Organism columns from its identifications, affected rows in `QuantifiedPeaks.tsv` reported groups they should not have. `Peptide` now copies, as `Identification` already did. Separately, `MergeResultsWith` now carries retention times and protein groups across for a peptide both runs saw, where it previously dropped both.

- **An `IExperimentalDesign` implementation that ships (#1208)** — every implementation of the interface lived in the `Development` project or a test fixture, so any caller had to write one before it could call the engine at all. `SampleExperimentalDesign` covers both modalities — one `ISampleInfo` per file for label-free, one per channel for isobaric — with `FromSamples` and `LabelFree` factories. It is keyed the way `PivotByFile` looks entries up (file name with extension, matched case-insensitively), and rejects two different paths that share a file name rather than merging them. Named for the samples it holds rather than plain `ExperimentalDesign`, because MetaMorpheus already has `EngineLayer.ExperimentalDesign` and the plain name made six of its TaskLayer files ambiguous.

- **Shared-peptide protein quantification runs (#1209)** — `QuantificationParameters.UseSharedPeptidesForProteinQuant` was a settable `bool` that made `Run()` throw `NotImplementedException`, with nothing saying so until a search had already finished. `GetAllPeptideToProteinMap` is implemented: a shared peptide contributes to every group it was assigned to. Row indices are sorted, because `AllBioPolymersWithSetMods` is a `HashSet` whose enumeration order is not guaranteed stable and roll-up results should not depend on it.

- **Top3 protein estimator (#1212)** — the average of the three most intense observed peptides ([Silva et al. 2006](https://doi.org/10.1074/mcp.M500230-MCP200)), as `Top3Aggregation` plus a named `Top3RollUp`. Unlike `SumRollUp`, the result does not scale with how many peptides the search happened to identify, which is what makes it usable for comparing abundance between different proteins rather than one protein across samples. Fewer than three observations average what is there rather than dividing by three. Not suitable as a collapse aggregation strategy, and documented as such.

- **Match-between-runs stays within a digestion agent (#1148)** — MBR maps identifications from one run onto peaks in another, which does not make sense across proteases: a Glu-C file cannot contain a tryptic peptide. `Identification` gains an optional `DigestionAgentName`, and a transfer is refused between files digested differently. **Inert until a caller populates that field** — unknown on either side means unrestricted, so existing callers see exactly what they saw before. Donors are chosen per (sequence, agent), so a file digested with one agent cannot take the donor slot from files sharing another and silently lose the transfer that should have happened. Scoped to `QuantifyMatchBetweenRunsPeaks`; IsoTracker's own cross-file borrowing is unrestricted and says so. Closes #1034, open since March 2018.

- **A merged match-between-runs peak is published once (#1202)** — it was added to `_results.Peaks` twice. Harmless to totals, but it doubled the peak in the output.

- **Test project nullable annotations (#1221)** — `<Nullable>annotations</Nullable>` on the test project, so the roughly 200 `string?` annotations already written there mean what they say. No production change.
