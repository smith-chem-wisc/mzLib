# mzLib 1.0.594 — one fragment-position convention, PRIDE retry and resume, and the first ptmQtl engine slice
**Source:** `1.0.593..1.0.594` (`0a808fec..57a4b0d5`, 12 PRs)
**Contributors:** @nbollis, @trishorts

The API is unchanged, but several changes give existing callers different answers. **Every C-terminal and
3′ ion read from a `.psmtsv` or `.msp` file now reports a `ResiduePosition` one higher than in
1.0.593**, so code that places ions on a sequence by that value draws them one residue off until it
moves with this release (first item). An FTP project listing that comes back empty now throws instead
of returning `[]`. Moderated statistics on fewer than 30 features give different p-values when no
spline size is given, and they throw on a non-finite covariate. Everything else is additive or a fix.
MetaMorpheus has to take MetaMorpheus#2868 before it takes this release; see **Downstream**.

## Breaking changes

- **Terminal fragment `ResiduePosition` is one convention everywhere (#1408)** — For C-terminal and
  3′ ions, `ResiduePosition` is now `length − FragmentNumber + 1`: the one-based position of the
  residue next to the break, counted from the N or 5′ end. For `PEPTIDE`, y2 is now position 6, where
  it was 5. Protein fragmentation already used this convention. The psmtsv reader
  (`SpectrumMatchFromTsv`, glyco PSMs included), the MSP spectral-library reader and RNA 3′ products
  (`OligoWithSetMods`) used `length − FragmentNumber`, and now agree with it. The contract is
  documented on `Product`. **Re-check anything that maps an ion to a residue by `ResiduePosition`.**
  MetaMorpheus's MetaDraw is the known case. Its `MetaDraw_SearchTaskTest` fails against this
  release until MetaMorpheus#2868 is in. **Unchanged:** N-terminal and 5′ ions, `FragmentNumber`,
  masses, annotations, and the coordinate the RNA phosphate-modification lookup uses.
- **An empty PRIDE FTP root listing throws (#1412)** — `GetProjectFilesFromFtpAsync` used to return `[]`
  when the FTP root answered 200 with no entries. That answer is now treated as a transport failure:
  it is retried, then thrown as `HttpRequestException`. Code that treated an empty list as "this
  project has no files" now sees an exception.
- **A non-finite covariate throws in empirical-Bayes moderation (#1398)** — A usable feature whose
  trend covariate is NaN or infinite used to be dropped silently. It now throws.
  `VariancePrior.Scale` is now a read-only wrapper, so it can no longer be cast back to `double[]`
  and changed.

## Changed answers

- **The empirical-Bayes trend size follows limma for small inputs (#1398)** — When no spline size is
  given, the variance-prior trend now uses limma `fitFDist`'s rule:
  `1 + (n ≥ 3) + (n ≥ 6) + (n ≥ 30)` basis functions, capped at the number of distinct covariate
  values. The old default fitted 4 basis functions where limma fits 2 or 3 below 30 features. So
  `FitPrior` / `Moderate` with a trend on fewer than 30 features give a different d0, s0² and
  p-values from 1.0.593. These now match `eBayes(trend = TRUE, legacy = TRUE)` to 1e-8, and limma 3.68.5
  fixtures pin each step of the rule. `splineBasisCount` is now `int?`, where null means limma's
  rule. A size you pass is used as before.
- **ProForma writes UniProt modifications by their UNIMOD id (#1403)** — `ProFormaSequenceSerializer`
  now tries the MetaMorpheus modifications first and falls back to every known modification. A
  UniProt-named mod that has a Unimod accession is written as `[UNIMOD:n]`, not by its `UniProt:`
  name. **Unchanged:** every MetaMorpheus modification serializes exactly as before. All 3,278
  entries in `Mods.AllKnownMods` were compared, and a test pins the MetaMorpheus set. Mass-only
  mods also resolve as before.
- **RNase MC1 also cleaves before pseudouridine (#1408)** — The `RNase_MC1` rule is now
  `[G]|U, [G]|Y`. Sequences carrying Ψ (`Y`) can yield more oligos. Sequences without it digest as
  before.
- **SDRF drafter: one organism per row in mixed-organism deposits (#1409)** — When PRIDE lists more
  than one organism, every row used to be written `not available`. A row now takes one of the
  record's organisms when its file name names exactly one, either directly (`Rat1`, `Ecoli`) or through
  a cell line (`HeLa`, `HEK293`). The cell is marked `inferred`, and its evidence names the name part
  it came from. Spike-ins, mixtures, two cues, a cue for an unlisted organism, and deposits described
  as mixed-proteome stay `not available`. Across 1,193 cached deposits, 1,801 cells change, in 27
  deposits. No other cell changes. 1,129 of the 1,156 changed rows that a curated SDRF also
  describes agree with it.
- **SDRF file-name patterns: codes and leading dates are not conditions (#1410)** — In
  `SdrfFileNamePattern`, barcode parts are now read as sample codes. A TCGA aliquot, a plate-well
  letter or a patient code (`A00H`) used to become fake factors, and patients were ranked as
  replicates within them. A leading short date (`02-01-18_...`) is now one acquisition date, not
  three numeric categories. Two-level designs are untouched. 13 of 1,068 scoreable drafts change.
  `SdrfDrafter` itself is unchanged.

## New

- **PRIDE downloads retry and resume (#1412)** — All five PRIDE GETs retry transient failures 3
  times, after 5 s, 20 s and 60 s. Transient means: a timeout, a stalled or short body, 408, 429,
  any 5xx, and the 403 EBI uses to rate-limit `ftp.pride.ebi.ac.uk`. A 429 or 503 `Retry-After`
  replaces the backoff, capped at 60 s. `DownloadFileAsync` resumes by byte range under an `ETag` or
  `Last-Modified` validator, so a file that changed on the server restarts instead of being spliced.
  It keeps a `.partial` file between calls, so the next call for that file resumes it. Paged search
  and file-manifest fetches retry only the failed page. When the retries run out, the last exception
  propagates unchanged, including its `failed with status NNN` message. No public API is added; the
  retry budget is internal.
- **ptmQtl: intensity site occupancy and PTM pairs (#1369)** — First slice of
  `Quantification/PtmQtl`. It takes plain tables, so a result file, a stored catalog or a binding can
  feed it. `SiteOccupancyCalculator` computes intensity occupancy per run, and gives every (site,
  run) an explicit state (`Quantified`, `Floor`, `CountOnly`, `NotDetected`), none of which is read as
  a zero. PTM–PTM and PTM–trait pair tests build on the statistics below. `Quantification` now
  references `StatisticalModels`, which the package already ships.
- **Statistics: logistic regression, random-intercept mixed model, Spearman and p-value
  combination (#1367)** — New in `StatisticalModels`:
  - `LogisticRegression.Fit`: IRLS. Separated outcomes are reported as `Separated` with NaN values,
    not as huge coefficients.
  - `MixedModel.Fit`: REML by default, ML optional, nlme's containment df.
  - `SpearmanCorrelation.Correlate`: exact p for n ≤ 9 without ties, asymptotic otherwise. The
    result names the method.
  - Fisher and weighted Stouffer combination.

  Each is pinned to frozen R outputs.
- **Statistics: maximum-marginal-likelihood variance prior (#1368)** —
  `VariancePriorEstimator.MarginalLikelihood` handles features with unequal residual df, which
  missing values always cause. On two public label-free datasets its d0 is within about 1% of
  limma ≥ 3.61's default, and its p-values are 3 to 6× closer to limma's than the legacy estimator.
  It is derived from the model, not ported from limma's GPL code. It is opt-in: the default stays
  `MomentsLegacy`, so limma-legacy parity is unchanged.
- **Covered, unmodified sites can report occupancy 0/N (#1411)** —
  `CalculateParentLevelOccupancy` takes an optional `sitesToReport`, and
  `BioPolymerGroup.ReportSitesSeenModifiedInAnySampleGroup()` fills it. A site a sample group
  covered but never saw modified is then written `0/N`, rather than being indistinguishable from a site
  it never covered. A group that cannot tell 0 from unlocalized writes nothing for that site.
  **Unchanged:** every existing caller passes nothing, and its output is byte-for-byte the same.
- **SDRF: isobaric (TMT, iTRAQ, DiLeu) design from an SDRF (#1380)** — `SdrfIsobaricDesign` writes
  MetaMorpheus's `TmtDesign.txt`, or returns `SampleExperimentalDesign` with an
  `IsobaricQuantSampleInfo` per channel. Otherwise it refuses, listing every reason, and writes nothing. The kit
  and the plex come from the caller and are never guessed: a TMT11 plex that left 131C unannotated
  looks exactly like TMT10. It applies the same checks as MetaMorpheus's `TmtExperimentalDesign.Read`.

## Fixes

- **The spectral contrast angle of proportional spectra is 1, not NaN (#1315)** —
  `SpectralSimilarity.SpectralContrastAngle()` returned NaN for two spectra of the same shape at
  different scales, which are exactly the pairs that should score best. Rounding could push the cosine
  to `1 + 1e-16`, outside `Math.Acos`'s domain. The cosine is now clamped inside
  `SpectralContrastAngle` only, and `CosineSimilarity()` is unchanged.
- **PSI-MOD accessions get one `MOD:` prefix (#1403)** — mzLib 1.0.590–1.0.593 wrote
  `[MOD:MOD:01956]` through `ToProFormaString`, and could not read a valid `[MOD:01956]`. Both sides
  are fixed. The reader still accepts the doubled form, because files written by those versions and by
  MetaMorpheus 1.1.11 exist on disk.
- **Polygamma's asymptotic series starts at 20 (#1398)** — At 10 its truncation error was about
  2e-13 relative, not the 1e-15 its comment claimed. At 20 it is below 1e-16.

## Downstream

- **MetaMorpheus** — **MetaMorpheus#2868 must merge before MetaMorpheus takes 1.0.594.** That PR
  works out terminal-ion positions from the terminus, `FragmentNumber` and sequence length rather than
  reading `ResiduePosition`, so it is correct against both 1.0.593 and this release. Without it,
  MetaDraw draws C-terminal ions one residue off and `MetaDraw_SearchTaskTest` fails. No file was added to
  or removed from `mzLib.nuspec`, so the installer needs no `Product.wxs` change.
- **FlashLFQ, ProteaseGuru, pyMzLib** — No framework or packaging change. Their upstream watchers
  open the bump pull requests.
