# mzLib 1.0.599 — Casanovo de novo predictions mapped onto protein databases, and a taxonomy tree from UniProt's reference proteomes
**Source:** `1.0.598..1.0.599` (`aad4426b..6fc4153f`, 3 PRs)
**Contributors:** @nbollis

These notes were written after the release, which was published on 2026-11-17 with GitHub's generated list only.

**MetaMorpheus can take this release with a pin change alone.** No package dependency, target framework or public
signature changed, and no DLL was added, so the installer needs nothing. `UsefulProteomicsDatabases.dll` grows by the
1.85 MB of taxonomy it now embeds.

Both features are new code that nothing in mzLib or MetaMorpheus calls yet. They were built for MetaMorpheus's parallel
search, which is not on its master.

Answers change for existing callers in two places:
- sliding decoys and entrapment partners now carry their target's NCBI taxonomy reference;
- a `.tsv` named `*MappingSummary.tsv`, or with a mapping summary's header, is now recognized as one.

**#1595's description is ahead of its merged code.** It describes retention-time errors on Chronologer's % acetonitrile
scale and a precursor-m/z check on spectrum lookups. Those are commit `9b5c4956`, pushed after the merge and in no
release. This release reports errors in minutes and does not check lookups. These notes describe what shipped.

## Breaking changes

None. No public signature, default, package dependency or target framework changed. The enum values
`SupportedFileType.DenovoMappingResult` and `Software.Mzlib` are new and appended last, so existing values keep their
numbers.

## Changed answers

- **Sliding decoys and entrapment partners keep their target's NCBI taxonomy reference, and only that (#1596).**
  Reverse decoys already did. With it, `Protein.NcbiTaxonomyId` gives a decoy or a partner the organism of the database
  it came from, which grouping by taxon needs.
  - `DecoyType.Slide` decoys had no database references; they now have one. A target with no taxonomy still gives a
    decoy with none.
  - A partner from `EntrapmentProteinGenerator` had an empty list. It still inherits no GO or any other reference, so
    1.0.598's #1541 rule stands. The foreign arm (`Random_foreign_`) is unchanged.
  - By reading of the code: `ProteinDbWriter` writes every reference, so an entrapment database written to XML gains a
    `<dbReference type="NCBI Taxonomy">` per partner. A UniProt-style FASTA header gains `OX=`.
  - By reading of the code: in `ReactomeMembershipTsv`, a partner now names its target's organism instead of none. Its
    pathway-less row can therefore read `no_reference` where it read `species_not_covered`. Decoys are skipped there, as
    before.
  - **What does not change:** MetaMorpheus's SDRF organism skips decoys (`PostSearchAnalysisTaskSdrf.cs:986`), so
    sliding decoys do not move it.
- **A mapping summary is recognized by name or by header (#1586).** `GetFileType` now reads a file ending
  `MappingSummary.tsv` as `DenovoMappingResult` by its name alone, before any header check. A `.tsv` that every reader
  refused is now accepted when its header has a mapping summary's columns.

## New

- **Casanovo de novo predictions mapped onto protein databases (#1586, #1595).** `Readers.DeNovoMapping.DeNovoMapper`
  reads Casanovo mzTabs and gives each database one `DeNovoMappingResult`:
  - how many predictions its targets explain, and how many its decoys explain;
  - their scores;
  - the retention-time error of the target hits.

  It is ported from MetaCurator's DeNovoMapper, so that MetaMorpheus's parallel search can score each transient
  database without an external step.
  - **Databases:** `MapDatabases(paths)` reads FASTA or UniProt XML, with decoys from `ProteinDbLoader`
    (`DecoyType.Reverse` by default). `MapDatabase(name, proteins)` maps proteins already loaded and counts the
    caller's `IsDecoy` proteins as decoys.
  - **When a prediction maps:** when its unmodified peptide comes from digesting a protein in the database. The default
    digestion is trypsin, 2 missed cleavages, length 7 or more.
    - I and L are the same residue on both sides, unless `ReplaceIWithL` is false.
    - A prediction counts once per database, as a target or a decoy, never both. A decoy peptide equal to a target
      peptide of the same database is not a decoy, as in `MslLibraryBuilder`.
    - Casanovo's out-of-tolerance scores, in [-1, 0), are shifted into [0, 1).
  - **Retention-time errors are in minutes:** the observed time minus Chronologer's prediction, mapped onto that file's
    minutes.
    - Each mzTab file gets its own robust fit (`IrtCalibration.Fit`). It is anchored on that file's predictions scoring
      at least 0.8 (`CalibrationScoreThreshold`), one per peptide, so every database is scored against the same fit.
    - A file with fewer than 20 anchors gets a warning and no errors.
    - `RetentionTimeCalibrations` holds each file's fit. Its "iRT" axis, and its `ResidualSd`, are Chronologer's %
      acetonitrile, not iRT.
    - `MapRetentionTimes = false` skips all of this.
  - **Observed times:**
    - They come from the mzTab, read as seconds unless `colunit-psm` says minutes. Casanovo writes `null` there, so in
      practice the spectra files are read.
    - A spectra file is matched by file name without extension, so the paths the mzTab recorded need not exist.
    - `index=N` is the Nth MS2 spectrum mzLib loads from the file, not the MGF `SCANS=` number.
    - Any `RetentionTimePredictor` can replace Chronologer. A predictor passed in stays the caller's to dispose; one the
      mapper creates, it disposes.
  - **A spectrum lookup can land on the wrong spectrum without any warning**, by reading of the code in #1595's review,
    not measured:
    - an MGF whose blocks mzLib drops or reorders (non-rising `SCANS=`, a block with no peaks);
    - an mzML whose `scan=N` is not mzLib's position in the file (an MS2-only or cut-down conversion).

    SCIEX and Bruker nativeIDs carry no `scan=`, so those predictions get no time.
  - **The summary file:** `DeNovoMappingResultFile` reads and writes it, culture-invariant. It has 18 fixed columns,
    then one prediction-count column per mzTab file. `DeNovoMapper.WriteSummary` appends `MappingSummary.tsv` to a path
    that does not end in it.
  - **Validated on real data, per the PRs:** 43 Casanovo mzTabs (1,718,306 predictions, a viral spike-in in saliva)
    against 12,973 viral proteomes, with MetaCurator's settings (SSRCalc3 in place of Chronologer).
    - Observed and predicted times match MetaCurator's for every PSM.
    - Target counts are equal for all 12,579 databases that can be compared.
    - Decoys are 7,415 against MetaCurator's 773. MetaCurator cut each reversed sequence at its target's cleavage
      positions, so most of its decoy peptides could never match. 86 of the 7,501 decoys found before #1595, on 29
      databases, were target-equal peptides; #1595 dropped them.
    - All 43 files calibrated, each with about 3,400-3,900 anchors and a residual SD of about 0.75-0.79 % acetonitrile.
- **A taxonomy tree with real ranks (#1596).** `UsefulProteomicsDatabases.Taxonomy` holds the taxonomy as a tree, keyed
  by NCBI taxon ID. Each taxon has its rank and its parent, so a family, an order or a shared genus is looked up, not
  guessed from a name ending.
  - **`TaxonomyTree`** gives:
    - `Ancestors`, `Children` and `AncestorAtRank`;
    - `TryGetLineage`, the eight ranks from domain to species;
    - `GroupByRank`, `TopLevelGroup` and `LowestCommonAncestor`.

    An empty answer says why. `RankNotAssigned` is a fact: many viruses have no order. `TaxonNotInTree` is missing
    data. `ProteomeTaxonMap` maps a UniProt proteome ID to its taxon.
  - **A pinned baseline:** `TaxonomyTree.LoadPinned()` and `ProteomeTaxonMap.LoadPinned()` give the taxonomy above
    UniProt 2026_04's reference proteomes.
    - **Size:** 37,623 proteomes and 68,941 taxa, embedded as two gzipped tables of 1.85 MB together.
    - **Cost:** they are read once, on first use, in about 0.3 s and 0.1 s. Together they take about 36 MB in memory,
      and a lineage lookup takes about 4 µs.
    - **Taxa UniProt names by number only:** 22 proteomes, UP000031433 among them, are in the map but their taxon is
      not in the tree. Asking about one answers `TaxonNotInTree`.
    - **What it is not:** the NCBI taxonomy ontology (about 600 MB), which `ControlledVocabulary` still leaves out.
    - **Licence:** UniProt data is CC BY 4.0, credited in `THIRD-PARTY-NOTICES.md`.
    - **Refreshes are tested:** `TestPinnedTaxonomy` pins the lineages of human, mouse, yeast, E. coli K12 and
      SARS-CoV-2, so a refresh that moves one of them fails a test.
  - **Your own taxa:** `TaxonomySnapshotTsv` reads and writes the two tables, plain or gzipped. `WithOverlay` adds a
    user's taxa or proteomes to the shipped ones but cannot redefine one.
  - **`UniProtTaxonomyClient`** builds a tree and map from UniProt over `DownloadEngine`:
    - `FetchAsync(query)` from any proteome query (default `reference:true`);
    - `FetchProteomesAsync(ids)` from a named list.

    The proteome listing gives each organism's whole lineage but not the organism's own rank. Those ranks are read
    from `taxonomy/taxonIds`, 200 per request. Rebuilding the baseline takes about 270 requests and a little over two
    minutes.
  - **`ProteinDbRetriever.UniprotProteomeCatalog(path)`** reads UniProt's downloaded proteome list and keeps every
    column, the taxon ID included, as `UniProtProteomeEntry`.
    - Column names match regardless of case. BUSCO and CPD are optional, because UniProt now serves `Proteome Id` and
      leaves out BUSCO and CPD by default.
    - `UniprotProteomesList` is unchanged, and still returns the header line as an entry.
  - **`AnnotationTableReader.Read(TextReader, fileName, ...)`** reads a gzipped or embedded table. A corrupt `.gz` is
    reported with the file name and line. The path overload behaves as before.
  - **Compared with the three tables parallel search uses today** (31,100 proteomes):
    - 30,711 (98.7%) are in the baseline. The other 389 are no longer reference proteomes, and `FetchProteomesAsync`
      places them.
    - Of the 14,528 bacterial proteomes in the baseline with a blank species in the old table, 14,515 now have one.
    - The family differs for about 230 bacteria and 1,070 viruses. Those checked are reclassifications since the old
      tables were made, such as Flaviviridae split into Hepaciviridae and Pestiviridae.
  - **Not covered:** RNA. `NucleicAcid` carries no taxon ID, so RNA decoys are untouched.

## Fixes

None to code that shipped before. #1595's corrections apply to #1586, which is new in this release too:
- mzTab times read as seconds;
- the target-equal decoy rule;
- the median of an even count;
- culture-invariant mass shifts;

## Downstream

### MetaMorpheus: a pin change only

- **It calls nothing these PRs changed.** `upstream/master` (on 1.0.598) has no use of `DeNovoMapper`, `Casanovo`,
  `TaxonomyTree`, `ProteomeTaxonMap` or `UniprotProteomeCatalog`.
  - It calls `ProteinDbRetriever.UniprotProteomesList` (`GlobalVariables.cs:868`), which is unchanged.
  - Its one `switch` over `SupportedFileType` (`BrukerDataDirectory.cs:72`) handles only Bruker types.
- **Output that changes with the bump:** a search with `DecoyType.Slide` gets decoys carrying the target's taxonomy
  reference. Its SDRF organism is unchanged.
- **The consumers of these features are on the parallel-search branch, not master.** They are the de novo evidence per
  transient database, and replacing `TaxonomyMapping`'s three embedded TSVs (7.7 MB, ranks guessed from name endings).
  #1615 (open) extends the mapper for them.
