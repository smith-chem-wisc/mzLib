# mzLib 1.0.598 — a MassIVE client, Reactome and KEGG annotation, reporter-ion signal-to-noise, predicted .msl libraries, and TMT input to the differential statistics
**Source:** `1.0.597..1.0.598` (from `4a183123`, 58 PRs)
**Contributors:** @trishorts

**MetaMorpheus cannot take this release with a pin change alone.** Two changes stop its bump PR passing CI:
- The package now depends on FluentFTP 55.1.0 (#1574). `FluentFTP.dll` lands in MetaMorpheus's build output, and its
  installer lists DLLs by hand, so `validate_installer_contents` fails until `Product.wxs` gains the component.
- `DigestionParams` has a new setting, `RespectCleavagePromotingModifications` (#1510). MetaMorpheus rebuilds
  `DigestionParams` argument by argument in two places and drops it, so
  `TaskWindowDigestionParamsTests.ASettingNoWindowShows_SurvivesASave("respectCleavagePromotingModifications")` fails.

Neither fix compiles or builds against 1.0.597, so the order is **release first, then one MetaMorpheus PR** that bumps
mzLib and makes both; see **Downstream**. Until it lands, mzLib's `integration` job stays red. It has been red since
#1510 merged (`063d81a4`, 2026-11-12), on that one test: 3,474 of 3,476 MetaMorpheus tests pass.

**Default digestion does not change.** Every cleavage change here (#1510, #1535, #1551) sits behind a flag that
defaults to false. #1186, which would have made bare `trypsin` proline-restricted, was merged and reverted (#1571) and
is **not** in this release: `trypsin` means what it meant in 1.0.597.

Several answers change for existing callers:
- SDRF modification cells that MetaMorpheus writes for TMT, phospho, acetyl and terminal modifications;
- mzML written from a Thermo RAW, which now names its instrument and carries Thermo's noise table;
- which peptides a sequence variant identifies, for proteases with a preventing residue or a long motif;
- `.msl` neutral-loss signs, missing retention times, merge winners, and values the writers now refuse;
- Koina requests in which one input is refused;
- `QuantificationEngine`, which now quantifies matches ambiguous only in where their modifications sit;
- the variance prior, robust fits and two-term fits of the differential statistics;
- SDRF design readers, which accept pooled references and several factor columns.

Six methods and constructors, one property, one record and one constant changed shape with no overload of the old
shape kept, so a binary built against 1.0.597 must be rebuilt. No target framework changed.

## Breaking changes

- **FluentFTP 55.1.0 is a new package dependency (#1574).** Both nuspec groups declare it, and
  `UsefulProteomicsDatabases` references it. Only the new `MassiveClient` uses it, but restore brings `FluentFTP.dll`
  into every consumer's build output. It is MIT-licensed and has no dependencies of its own.
  - **An installer that lists its DLLs by name must add `FluentFTP.dll`.** MetaMorpheus's `Product.wxs` is one.
- **Rebuild against this release.** These gained a parameter, and no overload of the old shape was kept:
  - the `DigestionParams` constructor: a last optional `bool respectCleavagePromotingModifications = false` (#1510);
  - the `DigestionMotif` constructor: an optional `IReadOnlyList<CleavageRequirement> cleavageRequirements` (#1510);
  - `CleavageBlockingPolicy.For`: an optional `IEnumerable<Modification> fixedModifications` (#1510);
  - the protected `DigestionAgent.FullDigestion`: an optional `List<int> cleavageSites` (#1510). This matters only to
    a subclass that calls it;
  - `TargetDecoyRescorer.Score`: twelve optional parameters, from `candidateGroups` to `networkTargetFraction` (#1456).
    The defaults give 1.0.597's scores; the folds now run in parallel;
  - `NestedMixedModel.Fit`: an optional `bool estimableRandomTermsOnly = false` (#1580).

  Source compiles unchanged. A binary built against 1.0.597 throws `MissingMethodException` until it is rebuilt.
  **Code that walks `DigestionParams`' constructor by reflection sees a new setting**; MetaMorpheus's settings test
  is one.
- **Source changes in two places:**
  - **`SiteTraitOptions.ExcludeCeiling` is now `bool?` (#1543).** It was `bool`, default `true`. Null, the new
    default, means true, except under the new `BoundCells = Sampling`, where it means false. Setting it still
    compiles; reading it as a `bool` does not (CS0266). Read `ExcludeCeiling ?? true` for the old meaning. Code that
    echoes the option now writes null.
  - **`GeneResolution`, a positional record, gains a 20th parameter, `EnsemblXrefAgreement` (#1578).** Source that
    constructs it, or deconstructs it into 19 variables, stops compiling.
- **`MslProteoformIndex.ProtonMass` is now `Chemistry.Constants.ProtonMass` (#1566):** 1.007276466879, was 1.007276.
  It is a public `const`, so code compiled against 1.0.597 keeps the old value until rebuilt. Proteoform neutral masses
  move by 4.7e-7 Da per charge.

## Changed answers

- **SDRF modification cells use Unimod's name and say which terminus (#1548).** This is the
  `comment[modification parameters]` column of every SDRF `SdrfBuilder` writes, so it reaches MetaMorpheus's SDRF
  output.
  - `NT=` is now Unimod's name for the accessioned record, when the embedded Unimod holds it.
  - A terminal modification gets `PP=` (`Protein N-term`, `Protein C-term`, `Any N-term`, `Any C-term`) and loses
    `TA=X`. A real residue stays, as in `TA=Q;PP=Any N-term` for pyro-Glu.

    | Modification | 1.0.597 | 1.0.598 |
    |---|---|---|
    | TMT on K | `NT=TMT10;AC=UNIMOD:737;TA=K;MT=Fixed` | `NT=TMT6plex;AC=UNIMOD:737;TA=K;MT=Fixed` |
    | TMT on the peptide N-terminus | `NT=TMT10;AC=UNIMOD:737;TA=X;MT=Fixed` | `NT=TMT6plex;AC=UNIMOD:737;PP=Any N-term;MT=Fixed` |
    | Phosphorylation on S | `NT=Phosphorylation;AC=UNIMOD:21;TA=S;…` | `NT=Phospho;AC=UNIMOD:21;TA=S;…` |
    | Protein N-terminal acetylation | `NT=Acetylation;AC=UNIMOD:1;TA=X;…` | `NT=Acetyl;AC=UNIMOD:1;PP=Protein N-term;…` |
  - **What does not change:** carbamidomethyl and oxidation cells, so a search with MetaMorpheus's default
    modifications writes the same SDRF. Nothing in mzLib reads `NT=` to decide anything.
- **mzML written from a Thermo RAW names its instrument (#1545).** `MzmlMethods` now resolves the RAW's free-text model
  to its PSI-MS term. It wrote the bare parent `MS:1000031`, and the file read back with no instrument. This covers
  every `ExportAsMzML` call, so calibration's `-calib.mzML` and spectral averaging's output too.
  - The tests read back `MS:1001742` (LTQ Orbitrap Velos) and `MS:1002416` (Orbitrap Fusion).
  - Found on real data: in an SDRF from MetaMorpheus 1.1.13 on PXD034564, 16 calibrated files read `not available`
    while their RAW twins read `NT=Orbitrap Fusion Lumos;AC=MS:1002732`.
  - A name that is not a specific model (a prototype, or a RAW that records only `MS`) still writes `MS:1000031`. In
    that case `SdrfBuilder` now writes `NT=MS`; it wrote `NT=millisecond;AC=UO:0000028`.
  - mzML-sourced writes are unchanged, and files written before this release keep `MS:1000031`.
- **Thermo RAW scans carry their noise table, and mzML keeps it (#1552).**
  - `ThermoRawFileReader` fills `MsDataScan.NoiseData` with the `[3, n]` table (m/z, noise, baseline) Thermo records
    for every Orbitrap scan. It was always null. Ion-trap scans have no table and stay null.
  - The mzML writer now labels the three arrays with PSI-MS's sampled-noise terms (`MS:1002743`–`MS:1002745`); it
    wrote them as unlabelled non-standard arrays. Both read paths read the new terms and the arrays earlier versions
    wrote.
  - **An mzML written from a RAW is therefore larger.** In the files the PR measured each table has 40 points: about
    1 KB per Orbitrap scan in memory, and three arrays of 1,284 base64 characters per scan in mzML. For 50,000 Orbitrap
    scans that is at least 64 MB more; this is arithmetic, not a measured file. Astral and other analyzers were not
    measured.
  - Spectra, peaks and `GetReporterIonIntensities` are unchanged.
- **`DigestionParams` has one more setting (#1510).** `RespectCleavagePromotingModifications` defaults to false and
  changes nothing while false. `Equals`, `GetHashCode` and `Clone` include it, and `ToString()` gains a 14th field.
  - A serializer that writes every property now writes it. In MetaMorpheus, saved task TOML gains
    `RespectCleavagePromotingModifications = false`, and so does the index cache key, so **every cached index is
    rebuilt once**. Old TOML without the line loads with false.
- **A sequence variant beside a peptide is judged by the protease's whole cleavage rule (#1542).**
  `PeptideWithSetModifications.IntersectsAndIdentifiesVariation` decided whether a variant created a peptide's cut from
  the one residue next to the bond, and only for motifs with `CutIndex` 0 or 1. It now asks whether the protease cuts
  that bond in the variant protein and not in the original.

  | Protease | Variant | Peptide | 1.0.597 | 1.0.598 |
  |---|---|---|---|---|
  | `trypsin\|P` | `MAEA[A→K]PTIDER` | `PTIDER` | identified, though `K\|P` is never cut | not identified |
  | `trypsin\|P` | `MAEK[P→A]TIDER` | `MAEK` | missed | identified |
  | `collagenase` | `MS[APA→GPA]GPALE` | `GPALE` | missed: `CutIndex` 3 was never read | identified |

  - Proteases whose motifs are one residue with no preventing residue (`trypsin`, `Arg-C`, `Asp-N`) answer as before,
    by reading of the code. Peptides that overlap their variant are unaffected.
  - In MetaMorpheus this moves the `Identified Sequence Variations` column, variant counts and the `IsVariantPeptide`
    PEP input, only in variant-database searches and only for peptides beside a variant.
- **`.msl` neutral losses are positive, as in `Product.NeutralLoss` (#1566).** The format documented a loss as
  negative, while `Product`, the MSP reader and Koina carry it positive, and `.msl` copied the value across unflipped.
  - The named codes (H2O, NH3, H3PO4, HPO3, H3PO4+H2O) are the same bytes and now decode positive: water reads
    18.010565. A Custom value keeps the sign it was stored with.
  - Files converted from MSP or Koina, which stored positive Custom losses, now read correctly with no rewrite. **A
    Custom loss written negative to mean a loss now reads as a gain.**
  - **Code that tested `NeutralLoss < 0`, or negated it, must flip its sign.** Fragment m/z and intensity are unchanged,
    so spectral angles do not move.
- **A missing `.msl` retention time is NaN, not iRT 0 (#1566).** iRT 0 is a real time, so "no time" could not be told
  apart from it.
  - `MslLibraryEntry.RetentionTime` defaults to NaN. `ToLibrarySpectrum` gives a null `RetentionTime`, so an `.msp`
    export leaves out `RT=`. An entry with no time passes every `QueryWindow` RT window.
  - Old files keep an exact 0.0 as 0.0. **A library converted from `.msp` without `RT=` lines by 1.0.597 or earlier
    holds 0.0 for "no time"; convert it again to get NaN.**
  - Test `double.IsNaN(entry.RetentionTime)`, not `== 0`.
  - `IrtCalibrationModel.ToIrt(NaN)` and `ToRtMinutes(NaN)` return NaN; they threw `IndexOutOfRangeException`.
- **`.msl` stays format version 3, and files read in both directions (#1562, #1566, #1582).** A file written by 1.0.597
  loads; a file written by 1.0.598 loads in 1.0.597, where named losses read negative as they always did there.
  - **The same content can now be written as different bytes than 1.0.597 wrote**, from the loss sign, the new status
    bits (#1582, zero unless set), and a canonical fragment order (#1562). Fragments tied in m/z were ordered by an
    unstable sort; ties are now broken on every stored field, so writing the same content twice gives the same bytes.
    Rewriting the dia project's 5.24 M-precursor library swapped two tied fragments in 5,902 entries.
- **`MslMerger.Merge` keeps the copy its policy names (#1566).** The default, `KeepFirst` with `deduplicate: true`, is
  affected.
  - `KeepFirst` keeps the first source's copy; it kept whichever came first in m/z order, and every reversed decoy ties
    its target in m/z. `KeepLast` writes the last copy once; it wrote every copy the last file held. `KeepLowestQValue`
    compares copies at any m/z; it compared only within 0.001 Da.
  - `DuplicatesSkipped` can change. An output path that is also a source is refused up front with `ArgumentException`;
    it threw `UnauthorizedAccessException` after all the work.
- **The `.msl` writers refuse what they used to store wrongly (#1566, #1582).** Every writer, `Save`, `UpdateAndSave`,
  `MslConverter.FromMspLibrarySpectra` and `MslMerger.Merge` throw `ArgumentException` before writing anything for a
  null entry; a precursor m/z that is not a finite float (no query could return it, and `Save(GetAllEntries())`
  silently dropped it); an infinite retention time (NaN is allowed); a precursor charge outside int16; a fragment
  charge outside 0–255 (-1 was stored as 255); an undefined `RtStatus`; and a `LibrarySpectrum` that cannot be
  converted, named by position (it failed with `NullReferenceException`).
  - A compression level outside [0, 22] is refused by `WriteStreaming` and `Merge` too; level 23 wrote compressed and
    -1 uncompressed.
  - No file written by 1.0.597 is refused on read. Rewriting one fails only if an entry holds an infinite retention
    time.
- **`MslLibrary.UpdateAndSave` treats only real times as times (#1566).** A psmtsv's -1 ("no time") was used as an
  anchor at -1. A fit whose anchors share one observed time is no longer reported as applied; raw minutes were stored
  labelled as iRT. A new entry with no time stores NaN, not the intercept. A replacement keeps `ProteinName` and
  `GeneName`.
- **Other `.msl` calls throw where they did not (#1566).** `MslReader.ReadHeaderOnly`, and so `CanLoadIndexOnly`,
  throw `FormatException` for a version outside [1, 3], as `Load` did. `WithCalibratedRetentionTimes` throws for a zero
  or non-finite slope (a NaN slope made every window match). `PredictFragments` throws on an index-only library, where
  it wrote into cached copies that eviction discards.
- **Koina: one refused input no longer fails the whole request (#1569).** Koina answers 400 for a whole request when a
  model raises on one input, and `Predict` threw, losing every other input; `PredictRetentionTimeEquivalents` marked
  every peptide `PredictionError`. The PR's case was `E[UNIMOD:954]` in a 500-sequence `Prosit_2025_irt_40PTM`
  request.
  - Such a 400 is now a `KoinaInputRejectedException`, which derives from `HttpRequestException`. All five model
    families split the request in half down to single inputs. The refused input gets `ValidInputsMask` false, a null
    prediction and the warning `Koina refused this input: …`; every other input keeps its prediction.
  - One refusal among n costs at most 2·ceil(log2 n) extra requests. Splitting stops after max(10, 1% of inputs)
    refusals and throws the first, as before.
  - **`ThrowException` mode** now throws `ArgumentException("Koina refused input …")`; it threw `HttpRequestException`.
  - 5xx, timeouts, network errors and malformed requests are never split and throw as before. A request nothing
    refuses goes out exactly as before.
- **Prosit 2025 22PTM and 40PTM refuse what Koina cannot place, before sending (#1567).** For the four
  `Prosit2025*22PTM` / `*40PTM` models: Unimod ids above 2072, an untrained modification on A, E, F, G, N, P or V, a
  composition with elements beyond H, C, N, O, P and S, and a negative atom count. Each such input failed the whole
  call with a 400. A refusal follows the handling mode: `ReturnNull` (default) gives null with a warning,
  `ThrowException` throws `ArgumentException`, `RemoveIncompatibleElements` drops the token.
  - **N-terminal pyro-Glu is now predicted**: `[UNIMOD:27]-E…` and `[UNIMOD:28]-Q…` are sent as the trained residue
    tokens. The returned sequence is unchanged.
  - The rule is read from Koina's source at `wilhelm-lab/koina@d176169`; if Koina changes those files, the lists must
    be regenerated.
- **`QuantificationEngine` quantifies a match ambiguous only in where its modifications sit (#1504).** This is on by
  default, with no switch.
  - A match with one base sequence, the same modifications and two or more possible sites was dropped and counted in
    `AmbiguousSpectralMatchesExcluded`. It now goes to a new `LocalizationAmbiguousPeptide` row whose `FullSequence`
    joins the open sites with `|`. "The same modifications" means the same identity (type, `OriginalId`, formula):
    phospho on S against T qualifies; oxidation on M against hydroxylation on D does not.
  - A row counts toward a protein group only when that group alone lists all its sites.
  - Existing rows, their order and values, normalization and roll-ups are unchanged. New rows come after the caller's
    peptides; a protein's value changes only if it gains one. `AmbiguousSpectralMatchesExcluded` falls accordingly.
  - **Single-valued members of such a row can throw `NotSupportedException`** when its sites disagree
    (`MissedCleavages`, `Parent`, `OneBasedStartResidue`, …), and `Fragment`, `FragmentInternally` and `Localize`
    always throw. Code that walks the peptide matrix should test for the type and read `Sites`.
  - **To keep 1.0.597's tables**, drop these matches before calling, as MetaMorpheus does (`includeAmbiguousMods:
    false`). How often a real search produces them under this rule is unmeasured.
- **A variance prior with infinite df and no trend takes the mean variance, as limma has since 3.32.0 (#1573).** This is
  `EmpiricalBayes.FitPrior` with no covariate and the default `MomentsLegacy`, on 3 or more features, when the prior df
  comes out infinite. The posterior variance was `exp(mean(log s²))`, limma's pre-2017 formula.
  - It reaches `Moderate` and `ModerateContrasts` with `trend: false`, `NestedMixedModel.ModerateContrasts`, and the
    new pooled overloads. Moderated SE, t, p and adjusted p change for every feature of such a fit.
  - Variances 0.10, 0.11 and 0.105 on 4 df: the prior goes from 0.1375 to 0.105, limma 3.68.5's value. Per the PR's
    simulation the old value was typically 1–9% off; two real TMT datasets had finite prior df and are unaffected.
  - A finite prior df, `trend: true`, `MarginalLikelihood` and fewer than 3 features are unchanged.
- **Robust `NestedMixedModel` fits that never settle fall back to one round (#1547).** This touches only `robust: true`,
  which shipped in 1.0.597 and is off by default. Reweighting that hit its 100-round limit, or whose later round had a
  zero MAD or a failed refit, was `NotConverged`. It is now fitted on round 1's Huber weights, msqrob2's default, with
  `Status` `Fitted` and the new `RobustFellBack` true.
  - **Every feature of such a fit can move**, because the fallbacks now inform the variance prior. In the PR's
    simulation, 0.15–2.6% of proteins fell back, matching R's rate. Weights match msqrob2 to 6.3e-9.
  - To leave them out, drop features where `RobustFellBack` is true.
- **`NestedMixedModel` with two random terms no longer stops on the zero-variance boundary (#1577).** Nelder–Mead
  clamped a negative θ to 0, leaving a flat region where it could stop beside a better interior optimum. On the
  MSstatsTMT controlled mixtures, 2 of 2,537 proteins moved, by up to 0.002 log2; O75569 now matches lme4. One-term fits
  are bit-identical, as are two-term fits whose simplex never stepped below 0.
- **`SiteOccupancyCalculator.CombineRuns` sums peptidoform counts and refuses an unknown state (#1543).** The combined
  `CoveringPeptidoforms` and `ModifiedPeptidoforms` were always null; they are now summed over fractions (an upper
  bound). A cell whose `State` is not a defined `OccupancyState` throws `ArgumentException`; it was combined as
  `NotDetected`.
- **SDRF design readers carry a pooled reference instead of refusing or comparing it (#1508).** `SdrfLabelFreeDesign`
  and `SdrfIsobaricDesign` mark a sample as a reference from any of `characteristics[sample type]` =
  `reference`/`pooled`, `comment[reference channel]`, `characteristics[pooled sample]`, or a `pooled` biological
  replicate (the SDRF specification's word).
  - **A `pooled` replicate no longer refuses the design**; a reference with no number gets one, and `Notes` lists it.
  - A reference is left out of statistics: `IsobaricQuantSampleInfo.IsReferenceChannel` is now set (it was always
    false), and the new `SpectraFileInfo.IsReference` marks label-free files. `SpectraFileInfo` equality ignores it.
  - **A design file gains a `Sample Type` column only when a reference is marked**: the 9th column of `TmtDesign.txt`,
    a trailing 6th of `ExperimentalDesign.tsv`. A design with no reference is written byte for byte as before.
  - A mark every sample carries marks none, with a note. Deposited examples: PXD048052 (TMT10) and PXD009086 were
    refused and now read, with their pools as references.
- **Several factor columns now make the condition when none is declared (#1587).** `SdrfLabelFreeDesign`,
  `SdrfIsobaricDesign` and `SdrfSearchDesign` join every `factor value[...]` column in SDRF order with `_`, with a
  note. This was refused ("Several factor value columns and none declared"). A single or declared factor column reads
  as before, and the remaining refusals now name the way out.
- **A shuffled entrapment partner carries no GO (#1541).** `GoAccessionAnnotation`, and so `GoGroupAnnotator`, ignore
  an entrapment entry's GO references, unless it is a foreign-proteome partner (`Random_foreign_<acc>`), which keeps its
  own. Such a member reads `no_go_terms`, and its unknown GO ids no longer refuse the database. This matters for
  databases whose partners copied their target's references; the 1.0.597 generator writes none. A foreign proteome
  loaded as entrapment without the `Random_foreign_` prefix now loses its GO.
- **Fourteen more lysine modifications block cleavage, when you ask (#1535):** twelve acylations (isovaleryl,
  pentanoyl, hexanoyl, tiglyl, 3-methylglutaconyl, glutaryl, pyruvoyl, glyoxylyl, itaconyl, glyceroyl,
  3-phosphoglyceryl, phosphogluconoyl) and two ubiquitin-like remnants (ValGly from UFM1, and Pup). Blocking entries go
  from 99 to 113 of 3,448. `Modification.BlocksCleavage` is true for them whatever the flag; digestion changes only
  with `RespectCleavageBlockingModifications = true`, which defaults to false.
- **A carbamylated lysine at a peptide's C-terminal cut is kept, when you ask (#1551).** With
  `RespectCleavageBlockingModifications = true`, carbamylation is exempt at the C-terminus, because urea's cyanate also
  carbamylates lysines after digestion: carbamyl-K's y1 is matched in 66.6% of 1,820 such peptides, against 0–11% for
  true blockers. Inside a peptide it still blocks. The new `CleavageBlockingModifications.MayFormAfterDigestion` makes
  the call.
- **Smaller output changes:** `GeneResolutionTsv` gains a last column, `ensembl_xref_agreement`; existing columns are
  unchanged, but a reader that pins the column count fails (#1578). The Retry-After key in `Exception.Data` is now
  `DownloadEngine.RetryAfter` (was `PrideArchiveClient.RetryAfter`); PRIDE's messages are otherwise byte-for-byte the
  same (#1534).

## New

- **A MassIVE client (#1574).** `MassiveClient` takes an MSV accession, or a PXD that MassIVE hosts.
  `GetDatasetAsync` reads the dataset record from MassIVE's PROXI service; `GetDatasetFilesAsync` lists every file with
  its exact size; `DownloadFileAsync` and `DownloadDatasetFilesAsync` download over FTPS with the certificate validated,
  size-checked before and after, resumable from `<file>.partial` only while it belongs to the same server file. An
  outage is `HttpRequestException`; a permanent refusal or a missing dataset is `MzLibException`; a PXD hosted at PRIDE
  gets a message that says so.
- **`ServiceFailure.IsTransient(Exception)` says whether a failure is worth retrying later (#1534).** True only for
  failures the retry loop judged transient and gave up on (timeouts, stalled or short bodies, 408, 429, 5xx, PRIDE FTP
  403s, MassIVE's transient FTP failures); false for everything else, including the caller's cancellation. PRIDE's
  download code moved into an internal engine that MassIVE shares; PRIDE's behaviour does not change.
- **Reactome and KEGG annotation, stored once per release and once per database (#1536, #1537, #1576).** These follow
  #1497's GO tables. Nothing here downloads or calls KEGG.
  - On `Protein`: `ReactomePathways` (with isoform scope), `KeggGeneIds` (such as `hsa:2597`) and
    `DisplayedIsoformId`, derived from `DatabaseReferences` like `GoTerms`. In UniProt 2026_03, Reactome covers 55% of
    human entries and KEGG 93%.
  - Per Reactome release: `ReactomeRelease.Load` pins Reactome's two files by sha256 and gives `Ancestors`, `Roots` and
    `HumanEquivalentId`; `ReactomeReleaseTsv` writes pathways, hierarchy and ancestors. Release 96 loads in about 0.3 s.
  - Per search database: `ReactomeAccessionAnnotation` and `ReactomeMembershipTsv` (status `annotated`,
    `no_reference` or `species_not_covered`), and `KeggGeneLinksTsv`.
- **Reporter-ion signal-to-noise (#1552).** `IsobaricMassTag.GetReporterIonSignalToNoise(MsDataScan)` gives one value
  per reporter ion, from the peak `GetReporterIonIntensities` picks, by Thermo's (intensity − baseline) / (noise −
  baseline). Over 761,570 reporter peaks on two HYpro16 files it matches Thermo's own S/N with a median relative
  difference of 6e-7. It is null for ion-trap scans and files with no noise table.
- **A protease can require an O-glycan at a subsite (#1510).** StcE cuts `S/T-X-S/T` only when P2 carries an
  O-glycan; matching the motif alone over-digests.
  - `proteases.tsv` gains an optional seventh column, `Cleavage Requirement`; `StcE` and `StcE-trypsin` get
    `P2:O-glycan`. A file without the column, such as an existing custom protease file, loads as before.
  - It is honoured only with `DigestionParams.RespectCleavagePromotingModifications = true`, in fully specific
    digestion. Then a site no O-glycan can reach is not a site. StcE on `RPPITQSSL` with an O-glycan possible at Thr5
    gives `RPPITQ` and `SSL` with the flag off, and `RPPIT*Q`, `SSL` and `RPPITQSSL` with it on.
  - MetaMorpheus has no control for the flag yet.
- **`MslLibraryBuilder` builds a predicted `.msl` library from proteins (#1393).** It digests targets and any
  entrapment proteins, makes reversed `DECOY_` decoys (dropping any that equal a target, with I = L), and predicts iRT
  per peptide and fragments per precursor in chunks. Entries carry `IsDecoy`, `IsEntrapment` and every source
  accession. `MslLibraryBuildResult` counts what was built and what a model rejected; rejections are never thrown.
- **`.msl` for large libraries (#1563, #1564, #1581, #1582, #1579).** Timings are the dia project's, per the PRs.
  - `MslLibrary.LoadIndexOnly(path, maxCachedEntries)` sets the entry cache; 0 turns it off. `LoadIndexOnly(path)`
    keeps 10,000 (`DefaultIndexOnlyCacheSize`).
  - `MslLibrary.CanLoadIndexOnly(path)` says from the header whether a file really opens index-only. A zstd-compressed
    5.24 M-precursor library loaded in full took 14.2 s and 13.9 GB, against 4.0 s and 1.9 GB index-only.
  - `ReadFragments(precursorIdx, Span<MslFragmentValue>)` and `GetFragmentCount` copy fragments into a caller's buffer
    with no allocation: 3.75 M entries in 0.65 s and 0 bytes, against 3.45 s and 5.83 GB with `GetEntry`.
  - `MslLibraryEntry.RtStatus` and `RtStruckByPrediction` live in reserved bits of the precursor flags byte, so there
    is no version bump; files written before read `None`. Nothing sets them yet.
  - `MslConverter.FromMspFile(path, out List<string> warnings)` leaves out spectra it cannot convert and reports each.
- **MetaMorpheus's DIA tables have a reader and writer (#1538, #1570).** `DiaPrecursorFile` reads and writes
  `AllDiaPrecursors.tsv` (one row per precursor per run) and `DiaPeptideFile` reads and writes `AllDiaPeptides.tsv`.
  Both start with `# contaminants: assessed` or `not assessed`, exposed as `ContaminantsAssessed`; a file without it is
  refused. Columns are read by name in any order. `SupportedFileType.DiaPrecursorTsv` and `DiaPeptideTsv` are appended
  last, so existing values keep their numbers.
- **`TargetDecoyPep` estimates posterior error probabilities from a score's target-decoy distribution (#1540).**
  `Estimate(scores, isDecoy)` or `Estimate(scores, decoyFraction)` fits the decoy share by weighted isotonic
  regression and reports `min(1, r / (1 − r))`, non-increasing in score. It matches scikit-learn to 1e-12, and on a
  simulated mixture its PEPs sum to the false targets within 3%. It does not replace either `PepAnalysisEngine`.
- **Target-decoy rescoring gains a neural-network ensemble (#1456).** Opt in with `TargetDecoyRescorer.Score(...,
  model: RescoreModel.NeuralNetworkEnsemble)`. Within each fold the linear discriminant still picks the training rows;
  small tanh networks (DIA-NN 2020's 25-20-15-10-5 by default) then train on them. Also new:
  `MultilayerPerceptron`, `MultilayerPerceptronEnsemble`, `TargetDecoyQValues.Compute` and `PickedTargetDecoy.Compete`.
  On MetaMorpheus's unreleased DIA search, per the PR, PXD022589 gave 64,844 precursors at 1% paired-entrapment FDP.
- **TMT and iTRAQ input for the differential statistics (#1559).** `IsobaricObservationTable.Build(design, psms,
  proteinGroups)` gives one row per peptide ion per plex run with each channel's log2 reporter intensity, from an
  engine-neutral `IsobaricPsm`. `IsobaricNormalization` moves each channel's median to the median of channel medians.
  On PXD007683 and the MSstatsTMT mixtures every value equals an independent R build within 1e-12. Nothing calls it yet.
- **`NestedMixedModel` additions (#1580, #1575, #1514).**
  - `Fit(..., estimableRandomTermsOnly: true)` drops random terms the data cannot estimate (lme4's own checks), down to
    least squares (`RandomStructure.None`). On the MSstatsTMT mixtures, 1,018 of 3,554 proteins refused today become
    708 with the individual term and 310 by least squares. `StructureOf` predicts the structure. The default is
    unchanged.
  - `NestedMixedModelFit.NuisanceCoefficients(feature)` returns each feature's nuisance fixed effects (lme4 `fixef` to
    1e-6). `ModerateContrasts` overloads over several fits moderate them under one variance prior.
  - `ReportedStatuses` on every model lists the `FeatureFitStatus` values it can report. The enum is unchanged.
- **`EffectScale` (#1553)** estimates c in scaled ≈ c × reference when both sets of effects carry error, by Zhao et
  al.'s (2020) estimator as in mr.raps (within 3e-10 of R), for pooling TMT with label-free. `Rescale` puts an effect
  on the reference scale; its SE has no covariance term.
- **`SiteTraitEffects.Fit` can use runs missing one intensity, as counts (#1543).** Opt in with
  `SiteTraitOptions.BoundCells = BoundCellModel.Sampling`. With the default, results are bit-identical to 1.0.597.
- **A set-level test of frozen hypotheses (#1506, #1572):** `SetTestFreeze`, `SetMemberResolver`, `SetModel` (matches
  lmerTest to 1.6e-6 in df), `SetVerdict` and `SetTest.Run` in `Quantification.Differential`. Nothing calls them yet.
- **`SdrfSearchDesign.Read(sdrf, searchedFiles, options)` says in one call whether an SDRF gives a usable design for
  exactly the searched files (#1561).** It joins, then reads with the label-free or isobaric reader, and never throws
  for a bad SDRF: a missing file or an empty join is a refusal.
  - The design readers can read a join (`Read(SdrfSearchScoping, options)`) and report the SDRF file's own line numbers
    (#1558, #1583).
  - Options `SingleCondition` and `UnknownFactorIsOwnCondition` let a caller state a grouping (#1587).
  - `SdrfIsobaricDesign.TmtDesignFileName` (`"TmtDesign.txt"`, #1546), the pooled-reference column constants (#1508),
    and `SdrfAge.TryParse(..., out SdrfAgeRefusal)`, `SdrfSampleBlock.InDocumentOrder` and
    `SdrfDocument.WriteResults(..., out writtenPath)` (#1549), which the language bindings had been rebuilding for
    themselves.
- **`GeneResolution.EnsemblXrefAgreement` (#1578)** splits rows where Ensembl's xref does not agree into `Silent` and
  `Disagrees`. On rat, "agrees" keeps 14,714 of 21,471 entries; "agrees or silent" keeps 18,203.

- **`ProteinDbRetriever.RetrieveProteome(..., GeneCentric.yes)` works again (#1554).** Since UniProt 2026_04

  2026_04 membership.

  MetaMorpheus writes as `Name: /3`, stopped the whole conversion with `NullReferenceException`. It now throws
  `InvalidDataException` naming the spectrum, or, with the new overload, leaves it out: PXReprise's 936,774-entry human
  library converts with 12 warnings.

  Windows matched no row, so the design was refused; pyMzLib's CI found it. On every platform a Bruker folder with a
  trailing separator (`a1.d/`) named no file. It now reads as `a1.d`.
- **`MslWindowResults.Dispose` returns its pooled array once (#1566).** Disposing twice let the next two `QueryWindow`
