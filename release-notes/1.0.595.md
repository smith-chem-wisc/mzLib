# mzLib 1.0.595 — DIA-NN 2.x parquet, a differential-statistics layer, and `.msl` at DIA scale
**Source:** `1.0.594..1.0.595` (`b1e925ff..2615953a`, 38 PRs)
**Contributors:** @pcruzparri, @trishorts

Three changes can stop existing input from working. **The human SUMO-1 and SUMO-2/3 remnants in
`Mods.txt` are now named `... on K`, not `... on D`**, so a saved `.toml` or result file that names
the old key no longer resolves it. **ProForma strings the reader used to accept by quietly dropping
part of them now throw.** **An empty entrapment identifier now throws instead of marking the whole
database as entrapment.** Several more changes give existing callers different answers. Two digestion
cases change: a no-proline rule (`trypsin|P` and its kin) now holds at the very ends of a sequence,
and variant proteoforms keep truncation products they used to drop. The Lactylation on K mass rises
by one hydrogen, and `T|D` and `ED` matches now export to spectral libraries as decoys. The package
takes one new dependency, Parquet.Net 6.1.0, and no file was removed. MetaMorpheus's installer needs
five new DLL entries to take this release; see **Downstream**.

## Breaking changes

- **The human SUMO remnants target K (#1432)** — `DVIEVYQEQTGG (SUMO-1 Site human)` and
  `DVFQQQTGG (SUMO-2/3 Site human)` were defined on Asp, so they could never be placed on the lysine
  they modify. Both now target K, and their keys become `... on K`. Formulas and masses are unchanged
  (C57H86N14O22, 1318.6041 Da; C41H60N12O15, 960.4301 Da). **A saved name ending `on D` no longer
  resolves.** MetaMorpheus warns `Unrecognized mod …; are you using an old .toml?` and runs the search
  without it. Re-select the `on K` entries.
- **ProForma refuses what it used to drop silently (#1462)** — `ProFormaReader.Read`, and
  `ProFormaMultiTermReader.Read` through it, now check the input before parsing:
  - Stacked terminal modifications, such as `PEPTIDE-[UNIMOD:2][UNIMOD:35]` or `[A][B]-PEPTIDE`, used
    to keep only the last mod. They now throw the new `ProFormaUnsupportedException`, which derives
    from `ProFormaParseException`, so existing `catch` blocks still see it.
  - `[P]?[A][B]-PEPTIDE` used to silently turn `A` into an unlocalized mod. It now throws the same
    exception.
  - Residues after the C-terminus (`PEPTIDE-[mod]K`, which read as `PEPTIDEK`) throw
    `ProFormaParseException`. So does a leading `-PEPTIDE`.
  - Modification-only strings (`[UNIMOD:1]`) used to throw `IndexOutOfRangeException`, even in
    `ReturnNull` mode. They now throw `ProFormaParseException`.

  `ProFormaSequenceParser.Parse` reports stacked termini as `IncompatibleModifications` and returns
  null in the non-throwing modes. **Unchanged:** single terminal mods, stacked residue mods,
  unlocalized, labile and global mods, and every example in the round-trip corpus. mzLib, MetaMorpheus,
  FlashLFQ and ProteaseGuru only *write* ProForma, so none of them is affected.
- **An empty entrapment identifier throws (#1396)** — Passing `entrapmentIdentifier: ""` to a protein
  or RNA loader used to match every accession, so the whole database loaded as entrapment without a
  word. It now throws `ArgumentException`, and so does `null`, which used to throw
  `ArgumentNullException`. **Unchanged:** the default `"Random"` and case-insensitive containment
  matching. The four loaders now share `ProteinDbLoader.IsEntrapmentAccession` instead of eight copies
  of the rule.
- **Recompile against this release** — Three public methods gained optional parameters:
  `DigestionParams`' constructor (#1119), `MslIndex.Build` (#1414) and `PtmPairEngine.CoVarying`
  (#1446). Source compiles unchanged. A binary built against 1.0.594 that calls one of them throws
  `MissingMethodException` until it is rebuilt.

## Changed answers

- **No-proline rules now hold at the ends of a sequence (#1320)** — `DigestionMotif.Fits` skipped the
  preventing residue when the cleavage residue was the sequence's first residue (cut-after motifs) or
  its last (cut-before motifs). So `trypsin|P`, `Lys-C|P`, `chymotrypsin|P`, `elastase|P` and
  `subtilisin|P` cut a leading `R|P`: `RPAAAAK` gave `R` + `PAAAAK`. It now stays whole. The same call
  builds peptide-level decoys (`GetReverseDecoyFromTarget`, `GetScrambledDecoyFromTarget`,
  `DecoySequenceValidator.ScrambleSequence`), so a peptide starting `KP` or `RP` gets a different decoy
  under these rules: `KPEPTIDER` reverses to `EDITPEPKR`, where it was `KEDITPEPR`. For RNA,
  `RNase_MC1` no longer cuts a 3′-terminal GpU and `Cusativin` no longer cuts a 5′-terminal CpC.
  **Unchanged:** plain `trypsin`, every internal site, and Met-initiated proteins, since no `|P` rule
  recognizes M.
- **Variant proteoforms keep more truncation products (#1339)** — `VariantApplication` dropped a chain,
  peptide, propeptide or signal peptide whenever its boundary fell on a residue the variant leaves in
  place. Those products are now kept and moved with the edit: in `PEPTIDE`, `T4→TAG` with chain 4–7 now
  yields chain 4–9, where it yielded nothing. A multi-residue substitution that shares an end residue
  is treated the same way. Variant-aware searches over UniProt XML or VCF variants with processing
  features produce more proteoforms in top-down and more peptides at product boundaries in bottom-up.
  **Unchanged:** a single substitution on the boundary residue (`T4→V`) still drops the product.
- **Lactylation on K is one hydrogen heavier (#1417)** — The `Mods.txt` formula was C3H3O2 (71.013304
  Da). It is now C3H4O2 (72.021129 Da), lactic acid less water, and cites Unimod 2114, so the ProForma
  writer emits `[UNIMOD:2114]`. Searches that enable it shift by +1.007825 Da. Regenerate any GPTMD
  database that carries it. It is a "Less Common" modification, not in MetaMorpheus's GPTMD defaults.
- **Entrapment decoys read as decoys everywhere (#1371)** — `ToLibrarySpectrum()` on
  `SpectrumMatchFromTsv` and `PsmFromTsv` tested `== "D"`. So an `ED` match exported as a **target**
  library spectrum, and so did an ambiguous `T|D` match. Both now export as decoys. In
  `ProteinGroupFromTsv`, `IsContaminant` is now true for joined labels such as `T|C`, and
  `IsEntrapment` for `T|ET`. `SpectrumMatchFromTsv.IsEntrapment` used `Contains('E')`, so it read
  Excel's "Output too long" placeholder as entrapment. It no longer does. A value that is not a label
  is now none of decoy, contaminant or entrapment. **Unchanged:** `IsDecoy` for every label MetaMorpheus
  writes today, and protein-group TSV output byte for byte. The labels themselves are now public, as
  `Omics.BioPolymer.DecoyContaminantTargetLabel` (`T`/`D`/`C`/`ET`/`ED`, `For(...)`, `DecoyFraction`,
  `EntrapmentFraction`).
- **TMTpro on H/S/T/Y no longer turns into TMT (#1419)** — The modification lookup stripped `pro`
  from TMT names, so `TMTpro on S` resolved silently to TMT, at 224.152 Da and the wrong Unimod
  accession. It now comes back unresolved, which the caller's `SequenceConversionHandlingMode` handles.
  The bundled `unimod.xml` (2017) has no TMTpro, so these do not resolve at all yet. **Unchanged:**
  TMTpro on K and on the N-terminus, through the TMTpro→TMT18 synonym, and MetaMorpheus's TMT names,
  which contain no `pro`.
- **The Unimod lookup follows a mod's own Unimod id (#1404)** — When the mzLib id matches nothing,
  `UnimodModificationLookup` now uses the modification's own Unimod reference. It chooses only among
  entries with the same formula on the same residue and terminus, so no mass changes and no mod moves.
  29 of all known mods resolve differently. Examples: N6,N6-dimethyllysine is `Dimethyl` (UNIMOD:36),
  not `Ethyl` (UNIMOD:280); trimethyllysine is `Trimethyl`, not `Propyl`; deamidation is `Deamidated`,
  not `Asn->Asp`. `UnimodSequenceSerializer` output changes to match. **Unchanged:** the Global, mzLib
  and Modomics lookups, ProForma serialization and the Koina path.
- **Koina predicts C-terminally modified peptides (#1314)** — `KoinaModelBase.TryCleanSequence` left
  the `-` separator in place, so every mzLib sequence with a C-terminal mod (`PEPTIDE-[Amidation on
  E]`) failed its residue check. Under `ReturnNull` it failed with no warning. These peptides are now
  predicted, or refused with a warning that names the modification. Retention-time and spectral-angle
  predictions that used to come back null for them now come back.
- **FlashLFQ normalization tolerates replicate gaps (#1422)** — On a design that skipped a biorep,
  fraction or techrep number, `IntensityNormalizationEngine` threw `Sequence contains no elements`. Or it
  skipped normalization silently, because its reference was fixed at condition 1, biorep 0,
  techrep 0. The Bayesian protein step threw `KeyNotFoundException`. Loops now walk the replicate
  numbers that exist, and the reference is the lowest-numbered one. Three edge cases change answers on
  designs that ran before:
  - A replicate that shares no peptides with the reference used to stop normalization of every later
    replicate. Now only that one is skipped, with a warning.
  - Techrep normalization uses the lowest techrep *number* as its reference, not the first file
    listed.
  - A design built directly with 1-based biorep numbers is now biorep-normalized. It never was before.

  MetaMorpheus and the FlashLFQ GUI build 0-based numbers and refuse gaps, so they see only the first
  two.
- **`MakeIdentifications` on lightweight matches carries real scores (#1425)** — For
  `LightWeightSpectralMatch` records, the q-value, PEP q-value and score handed to FlashLFQ were
  hard-coded to 0. They are now read from the file. When the file lacks the column, the value is NaN,
  and a NaN q-value fails the match-between-runs donor comparison. **Unchanged:** `SpectrumMatchFromTsv`
  and DIA-NN inputs, and FlashLFQ's own `.psmtsv` path, which does not use the lightweight reader.
- **`.msl` `UpdateAndSave` remembers whether RTs are calibrated (#1383)** — See the `.msl` item under
  **New**. A library 1.0.595 has already updated may skip RT normalisation on its next update where it
  used to apply it, because the library now records that its RTs are in minutes.
- **Index-only `.msl` entries are fresh objects after eviction (#1421)** — `GetEntry(int)` in
  index-only mode now returns a copy, so evicted fragments can be freed. Code that compares entries by
  reference, or edits a returned entry and expects the edit to persist, behaves differently. Full-load
  mode is unchanged.

## New

- **DIA-NN 2.x parquet reports (#1384)** — `DiaNnParquetReportFile` reads `report.parquet` into the
  existing `DiaNnPrecursor` records, so `GetQuantifiableResults` and FlashLFQ take it unchanged. A
  `.parquet` file is recognized by its columns (`Precursor.Id`, `Stripped.Sequence`, `Run`), not its
  name. Any other parquet throws `Parquet file type not supported`. `SupportedFileType.DiaNnReportParquet`
  is appended last, so existing values keep their numbers. The enum grows from 38 to 39 members.
  Columns DIA-NN 2.x dropped read as NaN or null, decoy rows are skipped, and plexDIA channels are not
  yet supported (#1433). Brings in Parquet.Net 6.1.0, managed only, with no native Arrow runtime.
- **Differential statistics, end to end** — Four PRs add a limma-style path from quantified peptides to
  a results table. Each part is pinned to R reference output:
  - **`ObservationTable` (#1455)** builds the observation table from FlashLFQ results or the stored
    peptide table (`FlashLfqObservations`). It sums fractions on the linear scale and averages
    replicates on the log2 scale. Missing values are NaN with a reason, never 0. Normalization is the
    median of ratios against peptides seen in every sample. The two sources give bit-identical tables:
    9,398 peptides, 0 differing cells.
  - **`AnalysisDesign` and `Contrast` (#1450)** add factors, covariates, strata and contrasts. Treatment
    coding matches R's `model.matrix` and `qr()$rank` on 14 reference designs. A confounded contrast is
    reported as `not_estimable`, not fitted.
  - **`EmpiricalBayes.ModerateContrasts` (#1452)** gives estimates, standard errors, moderated t,
    p-values, BH-adjusted p-values and confidence intervals. It matches limma 3.68.5's
    `contrasts.fit` + `eBayes` + `topTable(confint)` to 1e-8 on complete data. With missing values it
    uses each feature's exact covariance, where limma approximates. Every `LinearModel.Fit` now keeps
    p(p+1)/2 extra doubles per feature, about 0.8 MB per 10,000 features at p = 4.
  - **DEF-DIFF v1 (#1453)** writes `DifferentialResults.tsv` (56 columns) and
    `DifferentialResults.metadata.json`. Missing values are empty cells, numbers round-trip, and files
    are UTF-8 without BOM with `\n` line endings, so output is byte-identical across platforms.
- **One rule for which matches are quantified (#1425)** — `QuantifiedPsmRule` picks one confidence tier
  per result file: PEP q-value if PEP trained, else notch q-value, else q-value. It keeps a match only
  below 0.01. PEP counts as untrained when every PEP q-value is 2 or NaN, or every PEP is identical.
  `|`-ambiguous matches are never kept. Decoys that pass are kept for match-between-runs.
  `MakeQuantifiedIdentifications` applies the rule. `MakeIdentifications` still filters nothing.
- **Opt-in: a cleavage-blocking modification abolishes its site (#1119)** — With
  `DigestionParams.RespectCleavageBlockingModifications = true`, a fully specific digest drops a
  peptide whose C-terminal K or R carries a blocking variable or annotated mod, such as `PEPTK[Acetyl]`.
  It generates the read-through `PEPTK[Acetyl]PEPTR` instead and reports 0 missed cleavages.
  `Modification.BlocksCleavage` and `CleavageBlockingModifications` classify the mods: acylations and
  GG/SUMO remnants on K, citrullination on R. **Off by default, and the default digest is identical.**
  No shipped modification file sets anything. Semi, nonspecific and fixed mods are untouched.
  `DigestionParams` equality and `ToString()` now include the flag. MetaMorpheus task `.toml` files gain
  a `RespectCleavageBlockingModifications = false` line, which older readers ignore.
- **PRIDE checksums, checked as bytes arrive (#1427, #1449)** —
  `PrideArchiveClient.GetFileChecksumsAsync(accession)` returns each file's MD5 and size. A new
  `DownloadFileAsync(file, dir, PrideFileChecksum expected, overwrite, verifyMd5)` overload checks size
  always and MD5 on request. It hashes in the same pass as the download, and recognizes the
  `<Error><Code>` text EBI sometimes serves in place of a file. A mismatch deletes the partial file and
  downloads again from byte 0, within the existing retry budget. EBI had served about 23 of about 70
  multi-gigabyte files at the right size with the wrong bytes. With `overwrite: false`, a truncated
  existing file is downloaded again. **Unchanged:** the original `DownloadFileAsync` overload.
- **Ensembl Compara orthology snapshots (#1381)** — New in `UsefulProteomicsDatabases.Ensembl`.
  `OrthologySnapshot.Build` turns Compara homology dumps and gene trees into per-species-pair ortholog
  tables. `OrthologySnapshotWriter.WriteAsync` writes them as zstd parquet, with `views.sql` and a
  manifest. `Build` refuses to run without the dump of every species it covers: in Ensembl 116, every
  human–mouse row is in the mouse dump. `SpeciesSet` never chains pairwise calls into groups.
- **UniProt gene-centric proteomes (#1448)** — `ProteinDbRetriever.RetrieveProteome(…, GeneCentric.yes)`
  downloads one canonical protein per gene. With `Reviewed.all` that is UniProt's reference set: 20,652
  entries for human, 21,860 for mouse, 21,471 for rat. The file name gains `_genecentric`. Existing
  overloads send the identical request.
- **Pairwise protein alignment (#1428)** — New `Omics.SequenceAlignment.PairwiseAligner`: global
  affine-gap alignment. It defaults to BLASTP's BLOSUM62, gap open 11, extend 1, with free end gaps.
  `TryMapSourceToTarget` / `TryMapTargetToSource` map a residue across, and return false where it
  faces a gap. NCBI's BLOSUM62 is embedded in `Omics.dll`. Tables above 200,000,000 cells are refused.
- **`.msl` entrapment flag and a working `rt_is_calibrated` (#1383)** — `PrecursorFlags` bit 3 marks
  entrapment, so with the decoy bit a library entry can be T, D, ET or ED. `QueryWindow(includeDecoys)`
  returns ET with targets and ED only with decoys. The calibrated-RT bit was always written as 0 and
  ignored on read. It now round-trips as `MslLibraryEntry.RtIsCalibrated`. **The format version is
  unchanged.** Old files read as target/iRT exactly as before. Older readers ignore both bits, so they
  see ET as a target and ED as a decoy.
- **Entrapment FDP estimators (#1385)** — `StatisticalModels.EntrapmentFdp` implements the lower-bound,
  combined and paired estimators of Wen et al. 2025 (*Nat. Methods* 22:1454), plus a `Sweep` over q-value
  thresholds. Estimates are not capped at 1, and `Paired` is reported only at r = 1. Deduplicate to the
  unit you are estimating before calling it.
- **Variant proteoform accessions (#1382)** — `VariantApplication.ParseAccession` inverts
  `GetAccession`: `P12345_S70N_A80T` gives entry `P12345` and variants `S70N_A80T`, and RefSeq
  `NP_000537.3_R72P` splits correctly. A collision counter (`P12345_2`) or a decoy/contaminant prefix
  is reported as unrecognized, not guessed.
- **ptmQtl: fractions and run level (#1430, #1446)** — `SiteOccupancyCalculator.Calculate(observations,
  runToSample, …)` sums a fractionated sample's fractions before computing occupancy, so 31 fractions
  are one sample, not 31 runs. `PtmPairEngine.CoVarying(removeRunLevel: true)` correlates co-varying
  pairs given each run's median occupancy, through the new partial Spearman
  (`SpearmanCorrelation.PartialCorrelate`, which matches `ppcor::pcor.test` to 1e-8). On real data
  this cut significant pairs from 597 to 369. Both default off, and the per-run overloads are unchanged.
- **SDRF: copy a sample's columns verbatim (#1451)** — With `SdrfSample.CopiedFrom` set,
  `SdrfBuilder.Build` writes the input row's sample columns cell for cell, keeping order, repeats and
  unknown keys, and still builds the assay columns. 12,264 of 12,298 curated SDRFs rebuild, and the
  other 33 are refused with a reason. `SdrfSearchScope` and `SdrfSearchScoping` are now public. Without
  `CopiedFrom`, output is unchanged.
- **`AveragineFormula` is public (#1413)** — FlashLFQ's averagine fill is now
  `MassSpectrometry.AveragineFormula`, with `GetAnchoredDistribution` anchoring the all-light
  isotopologue at a given monoisotopic mass. FlashLFQ's isotope distributions are pinned value for
  value against the old code. A NaN or infinite identification mass now throws where it used to
  produce garbage.

## Performance

`.msl` spectral libraries, measured by each PR's author:

| What | 1.0.594 | 1.0.595 | PR |
|---|---|---|---|
| 3M parallel `MslIndex.GetEntry` calls, 32 threads, index-only | 110–124 s | 0.65–0.69 s | #1414 |
| PXD022589 DIA extraction | 3:47 | 0:24 | #1414 |
| PXD022589 DIA calibration + search | 7:26 | 3:18 | #1414 |
| 2M `LoadFragmentsOnDemand` calls, 32 threads | 42 s | 0.53–0.73 s | #1420 |
| `LoadIndexOnly` open, 1M precursors | 1.39 s | 0.85 s | #1420 |
| Memory still held after one index-only pass, 1M entries | 847 MB | 10 MB | #1421 |
| Opening a 3.4 GB, 10M-precursor library | threw | 29 s cached, 113 s cold | #1420 |

PXD022589 returns the same 59,057 identifications at 1% before and after. Libraries over 2 GB now
open: `Load` and `LoadIndexOnly` stream the file instead of reading it whole. Index-only fragment
reads are lock-free, with memory-mapped reads on local fixed drives. That raised the measured
index-only working set by 15–27 GB relative to a full `Load`, because mapped pages count. The new
`GetEntry(i, includeFragments: false)` returns metadata without touching disk. **Format:** files under
2 GB are unchanged. A file over 2 GB with custom neutral losses cannot have its losses found by readers
up to 1.0.594. Parsing is stricter, so a malformed file that used to load may now throw
`FormatException`.

## Fixes

- **Median polish crashed on colliding sample names (#1424)** —
  `CalculateProteinResultsMedianPolish` counted samples by `Condition + BiologicalReplicate` as one
  string. So condition `A1` biorep 0 and condition `A` biorep 10 were both `A10`, and the run threw
  `IndexOutOfRangeException`. It now counts (condition, biorep) pairs. Designs without a collision get
  identical results.
- **Prosit 2020 TMT models refuse a mode that could never work (#1389)** — With `UsePrimarySequence`,
  which strips the TMT label these models require, `Prosit2020iRTTMT` and `Prosit2020IntensityTMT`
  built fine and then rejected every peptide. They now throw `ArgumentException` at construction. An
  undefined handling mode no longer lets an unlabeled peptide through. The defaults are unchanged.
- **Test-only (#1454, #1458, #1429)** — The live iRT TMT test uses a real TMTpro name. A ProForma test
  no longer depends on shared state. A clamp that never fired is removed from the likelihood
  variance-prior fit, and its tied-knot test now covers both estimators. No production change.

## Downstream

- **MetaMorpheus** — **The bump needs five `Product.wxs` components, so build it by hand rather than
  taking the watcher's pin-only PR**, as for 1.0.593 (MetaMorpheus#2869). Parquet.Net brings
  `Parquet.dll`, `CommunityToolkit.HighPerformance.dll`, `K4os.Compression.LZ4.dll`,
  `Microsoft.IO.RecyclableMemoryStream.dll` and `Snappier.dll`, none of which the installer lists
  (`ZstdSharp.dll` it already has, and 0.8.8 keeps the same file name). Without them
  `Validate Installer Contents` fails. MetaMorpheus master is green against this code: mzLib's
  `integration` job passed at `2615953a`. This release unblocks MetaMorpheus#2854, which needs
  `DecoyContaminantTargetLabel` (#1371), and the quantified-match rule port, which needs #1425.
- **ProteaseGuru** — Its default proteases are the `|P` variants, so #1320 can change the peptides it
  shows for a sequence that starts with K, R, F, W, Y or L followed by P. Its watcher opens the bump.
- **FlashLFQ** — Pin bump only. #1422 is the fix trishorts/FlashLFQ#3 needs. Its watcher opens the
  bump.
- **pyMzLib, mzLibRust, mzLibR** — `SupportedFileType` goes from 38 to 39, and the new type is
  quantifiable, so the bindings' counted claims move with it. The watcher writes only the pin, so
  pre-empt it. No target-framework change.
