# mzLib 1.0.597 — PSI-MOD charges from a table, TopDownProteomics 0.0.301, an entrapment database generator, and faster file I/O
**Source:** `1.0.596..1.0.597` (`cc67b7a2..03a49c77`, 28 PRs)
**Contributors:** @acesnik, @nbollis, @trishorts

**MetaMorpheus cannot take this release with a pin change alone.** Two changes stop its bump PR building:
- The package no longer ships `PSI-MOD.obo.xml` (#1415), and MetaMorpheus's installer lists it (`WIX0103`).
- The package now needs TopDownProteomics 0.0.301 (#1505), and MetaMorpheus pins 0.0.299 directly (`NU1605`).

The order taken is **release first, then one MetaMorpheus PR** that bumps mzLib and fixes both; see
**Downstream**. Until it lands, mzLib's `integration` job stays red. It has run no MetaMorpheus test since 2026-10-30.

Several answers change for existing callers:
- modification masses and names, from refreshed Unimod and UniProt data;
- `LogitNormalMixedModel` p-values for count features;
- median-polish protein values;
- FlashLFQ match-between-runs decoys;
- iRT calibration, which gains a default anchor guard;
- ProForma reading of stacked and labile modifications;
- PRIDE project downloads, which now refuse damaged files.

Four public methods or records changed signature with no overload kept, so a binary built against 1.0.596 must be
rebuilt. No target framework changed.

## Breaking changes

- **`PSI-MOD.obo.xml` is gone from the package; `PsiModFormalCharges.tsv` replaces it (#1415).**
  - The nuspec drops `modificationData\Data\PSI-MOD.obo.xml` and adds `modificationData\Data\PsiModFormalCharges.tsv`:
    86 rows of `MOD:nnnnn` → signed formal charge, from PSI-MOD.obo 1.039.0. The copy embedded in `Omics.dll` is gone
    too.
  - Read it with `ModificationLoader.ReadFormalChargesDictionary(string | TextReader)`.
  - `Loaders.LoadPsiMod` is unchanged: when the XML is missing it still downloads it, from smith-chem-wisc/psi-mod-CV
    (the 2014 file, 4.27 MB). Offline, that throws `HttpRequestException`. Move to the table rather than rely on it.
  - `Mods` and `GlobalModificationLookup` read only their embedded copies, so they need no file on disk.
  - An installer that lists the package's data files by name must drop the XML and add the table. That includes
    MetaMorpheus's `Product.wxs`.
- **TopDownProteomics 0.0.301 or later is required (#1505).** Both nuspec groups now declare
  `TopDownProteomics >= 0.0.301` (was 0.0.299).
  - A project that references 0.0.299 directly fails restore with `NU1605` (package downgrade), which the SDK treats
    as an error. Move the direct reference to 0.0.301.
  - MetaMorpheus does this at `EngineLayer.csproj:41`. FlashLFQ, ProteaseGuru and the bindings have no direct pin;
    they get 0.0.301 through mzLib.
- **Rebuild against this release.** These gained a parameter with no overload of the old shape kept:
  - `NestedMixedModel.Fit(..., int maxThreads = -1, bool robust = false)` (#1499);
  - `LogitNormalMixedModel.Fit(..., IReadOnlyList<string>? testedCoefficients = null)` (#1522);
  - `IrtCalibrationOptions`, a positional record, gains a sixth parameter `MinimumBinShare` (#1500). Source that
    deconstructs it into five variables stops compiling;
  - `DecoySequenceValidator.PermutationSpaceSize` and `UnrankPermutation` gain an optional `alsoHeldInPlace` (#1271).

  Source compiles unchanged, apart from that five-variable deconstruction. A binary built against 1.0.596 throws
  `MissingMethodException` until it is rebuilt. MetaMorpheus calls none of these.
- **Koina subclasses and hand-built predictions (#1392).**
  - The protected virtual `KoinaModelBase.TryCleanSequence` now returns the sequence in mzLib notation. The Koina API
    string still comes out through `out apiSequence`. An override must adapt.
  - Under `FragmentIonMappingMode.MapToValidatedFullSequence`, a prediction now needs the new `CleanedFullSequence`, or
    `GenerateLibrarySpectraFromPredictions` throws `InvalidOperationException`. The Koina models set it. A
    `PeptideFragmentIntensityPrediction` built by hand must set it too.
  - `MapToInputFullSequence`, the mode MetaMorpheus and ProteaseGuru use, is unchanged.

## Changed answers

- **Modification data is refreshed (#1415).** Unimod moves from 2017-12 to 2026-02-17, and UniProt `ptmlist.txt` from
  2026_01 to 2026_03.
  - **Masses that move:**
    - 29 N-glycans are about 1 Da lighter (1299.19 → 1298.476).
    - N,N,N-trimethylglycine goes from C3H7 to C3H6 (43.0548 → 42.0470).
    - Charged modifications now take their mass from the corrected formula. The other ten move by less than 4e-7 Da.
  - **Unimod names that change:**
    - 10 formulas are fixed.
    - 4 records are renamed; 1849 "2-hydroxyisobutyrylation" is now "hydroxyisobutyryl".
    - 5 records are deleted: Bodipy, Chlorpyrifos, Ethoxyformyl, NO_SMX_SMCT and Ub-amide.

    **A saved task or database that names a renamed or deleted record no longer resolves it.**
  - 89 Unimod and 2 UniProt entries are new.
  - **What does not change:** 206 modification names appear in 100 MetaMorpheus PRIDE reanalyses. None resolves
    differently.
- **106 UniProt modifications now report a Unimod id (#1416, #1524).** An embedded cross-reference table links UniProt
  entries to Unimod records that UniProt itself does not cite. It covers 22 lysine acylations and similar (#1416), plus
  84 more (#1524): Hex, oxidation, methyl, HexNAc, dioxidation, Hep and 23 complex N-glycan compositions.
  - `Modification.DatabaseReference["Unimod"]` and `GlobalModificationLookup`'s `UnimodId` are filled.
    `TryResolve("UniProt:N6-succinyllysine on K")?.UnimodId` is now 64.
  - ProForma and Unimod-notation output now write `[UNIMOD:n]` for these entries. (3R)-3-hydroxyarginine was
    `[MOD:01956]` and is now `[UNIMOD:35]`.
  - UniProt's own Unimod reference always wins.
  - 21 entries are left unlinked on purpose: 15 are different chemistry and 6 are arguable.
    (E)-2,3-didehydrobutyrine stays unlinked because a MetaMorpheus mzIdentML test pins it (MetaMorpheus#2884).
- **`LogitNormalMixedModel` on count features (#1522, fixes #1511).**
  - `PValue` for a feature with counted samples is now a likelihood-ratio test, from ML fits whatever the estimator,
    read against F(1, containment df). It was a Wald test. It is NaN when the containment df cannot be formed.
  - The new `FeatureFitStatus.Unbounded` marks a coefficient whose likelihood stays flat along a ridge. Its β and SE are
    NaN, and its p-value stands. **A caller that keeps only `Fitted` features should keep `Unbounded` too.** The new
    value is appended last, so existing values keep their numbers.
  - Separated counts under REML now report `Separated`, not `NotConverged`.
  - `FitLink`'s values change.
  - Features with nothing counted keep a bit-identical t test.
  - On #1511's layout A (ML), the fit was τ² 233, β1 22.9, p 0.013. It is now `Unbounded` with LR p 0.108, R's exact
    value. 1,575 likelihoods are within 1e-8 of exact integrals; the error was up to 0.6.
  - Count fits cost more: two extra ML fits per tested coefficient. Pass `testedCoefficients` to test only the ones you
    read.
- **Median polish values proteins whose peptides are each seen in one, different sample (#1486).**
  `MedianPolishRollUp.QuantifyGroup`, and so `FlashLfqResults.CalculateProteinResultsMedianPolish`, gave such a group
  NaN or one shared, meaningless number. Each observed sample now gets its own peptides' value. On a 4-file islet
  search, groups with a value went from 2,817 to 2,938 of 2,999 targets at 1%. None lost a value. Groups with a peptide
  in two or more samples are unchanged.
- **FlashLFQ match-between-runs decoys are drawn by rendezvous hashing (#1507).**
  - Every random-RT decoy is drawn again, once, on upgrade, so MBR PEP, q-values and accepted transfers change.
  - After that, an unrelated change to a search re-draws far fewer of them. On PXD009792, decoys that stay the same
    between two searches rose from 93% to 96%. The transfers that flip fell from 45.7% to 25.1% in one file, and from
    35.7% to 29.9% in another.
  - Renaming a spectra file now re-draws its decoys, because the draw keys on file names.
  - Identifications and MS/MS-detected peptide values do not change. #1484 stays open.
- **iRT calibration sets aside anchors in near-empty stretches by default (#1500).**
  - `IrtCalibration.Fit` drops anchors in any of 20 stretches (`IrtCalibration.DensityBins`) that holds under 5% of the
    busiest one.
  - `AnchorCount`, `FirstAnchor` and `LastAnchor` now describe the anchors the fit used.
  - Pass `MinimumBinShare: 0` for 1.0.596's fit. `IrtCalibration` shipped in 1.0.596, so its callers see the change.
  - On PXD022589, precursors at 1% rose from 53,437 to 54,126, and the residual SD fell from 3.31 to 2.83 iRT.
    PXD005573 is unchanged.
- **ProForma stacked and labile modifications are read whole (#1505).**
  - `ProFormaReader.Read` returns stacked termini (`[A][B]-PEPTIDE`, `PEPTIDE-[A][B]`, `[P]?[A][B]-…`) in
    `NTerminalModifications` / `CTerminalModifications`. `N/CTerminalDescriptors` hold only the first.
  - Every labile group is kept. Before, `{Glycan:Hex}{Glycan:NeuAc}` silently dropped Hex.
  - `ProFormaUnsupportedException` is no longer thrown, though the type remains. Malformed strings are still refused.
  - **`ProFormaConverter.ToModificationDictionary` now throws `MzLibException` for a stacked terminus.** A caller that
    catches only `ProFormaParseException` will miss it.
  - `ProFormaSequenceParser` is unchanged: it still refuses two terminal modifications.
- **PRIDE project downloads check every file (#1518).**
  - `PrideArchiveClient.DownloadProjectFilesAsync` keeps its signature. It now fetches the project's checksum list and
    sends each listed file through the size and error-text check.
  - A damaged file throws `MzLibException` after the retries; before, it was returned as downloaded.
  - An unreadable checksum list fails the call before any download. The call makes one or two extra requests.
  - A listed file whose own bytes contain `<Error><Code>` is refused.
  - Files with no checksum row (`generated/`) still download unchecked.
- **UniProt isoform scope is kept (#1501).**
  - Loaded `DatabaseReferences` carry the new `Molecule`. `DatabaseReference.Equals` compares it, and returns false
    rather than throwing for an argument that is not a `DatabaseReference`.
  - A sequence variant scoped to `<location sequence="ACC-n">` is applied when n is the entry's displayed isoform.
    Before, it assumed -1.
  - `ProteinDbLoader.Merge` keeps sequence attributes; before, it reset them.
  - `ProteinDbWriter` writes `<molecule>`, and a minimal `alternative products` comment, when present. XML without
    these elements is written as before.
- **UniProt's streaming-error page is an outage, not a missing entry (#1529).** A 200 whose body is "Error encountered
  when streaming data" now throws `HttpRequestException`, with no status code, from:
  - `TryRetrieveEntry`, which returned "not found";
  - `RetrieveEntry`, which threw "deleted/demerged";
  - `RetrieveProteome` and `DownloadAvailableUniProtProteomes`, which saved the error page as a successful download
    and now write nothing.
  It is not retried.
- **A merged protein group's decoy, contaminant and entrapment flags follow its members (#1526, fixes #1516).**
  `BioPolymerGroup.MergeWith` recomputes `IsDecoy`, `IsContaminant` and `IsEntrapment`. Before, a merged group kept the
  surviving group's flags. In MetaMorpheus parsimony, a real protein merged with its `Random_` entrapment partner read
  as a target whenever the real accession sorted first.
- **GO annotation corner cases (#1497).**
  - A variant of a GO-less isoform that is in the database (`P04406-2_A20T`) now inherits its entry's terms. It read
    `no_go_terms`.
  - A collision accession such as `P12345_2` now reads `no_entry`. It took P12345's terms.
  - On PXD007188, every other row (655,321) is byte-identical.
- **`FragmentCoElution.Score` treats a numerically flat fragment as flat (#1503).** A fragment whose spread is below
  1e-20 of its sum of squares no longer correlates rounding noise; one test case scored 0.074. `FindApex` can move in
  that case. Otherwise `Score` matches 1.0.596 to 1e-12.
- **RNase T1 cuts after inosine (#1521).** Its motif goes from `G|` to `G|,I|`. RNA without I digests as before.
- **Eight more lysine acyl amides block cleavage, when you ask (#1513):** methacryl, isonicotinyl, lipoyl, decanoyl,
  myristoyl, palmitoyl, stearoyl and lactoyl. Digestion changes only with `RespectCleavageBlockingModifications = true`,
  which defaults to false. Palmitoyl on C and myristoyl on G stay non-blocking.

## New

- **A managed entrapment database generator (#1271)** — `UsefulProteomicsDatabases.EntrapmentGeneration`.
  - **Entry points:**
    - `EntrapmentProteinGenerator.GenerateEntrapment(targets, digestionParams, forbiddenSequences, …, foldCount, seed)`;
    - `GenerateForeignEntrapment`;
    - `EntrapmentAccession` (`Random_<target>_f<fold>`) and `EntrapmentPairing.TryResolve`;
    - `EntrapmentReportBuilder`, with a TSV report and an exclusion sidecar.
  - Each entrapment protein is isomeric with its target: same composition, the same candidate sites, and the same
    cleavage sites.
  - **Refused with `MzLibException`:**
    - an agent that cannot hold its sites in place: an empty, wildcard, multi-residue or preventing-cleavage motif
      (`trypsin|P`'s `K[P]`, for example);
    - a mode that is not fully specific;
    - decoy, entrapment or contaminant targets;
    - duplicate accessions;
    - `RespectCleavageBlockingModifications`.
  - **Measured** on the reviewed human proteome with trypsin, MC ≤ 2:
    - r = 1 builds in 24.5 s, with 0.87% named collisions;
    - r = 9 builds in 125–140 s, with 7.7% named collisions.
  - `EntrapmentFdp.ClassifyExclusion` now accepts the generator's `truncationProductPeptide` reason as `Unpairable`
    (#1502). Before, the estimator threw on any sidecar built from a UniProt XML database.
- **Semi-supervised target-decoy rescoring (#1391)** — `StatisticalModels.LinearDiscriminant` and
  `TargetDecoyRescorer.Score` (cross-validated, iterated), with `RescoreStatus`. On PXD005573 HeLa, targets at 1% FDR
  went from 19,641 to 23,571. It does not replace MetaMorpheus's `PepAnalysisEngine`.
- **`NestedMixedModel`:**
  - **`robust`** (#1499) refits with msqrob2's weights to convergence. It reports `Weights(feature)`,
    `RobustIterations` and `RobustConverged`. A robust fit that cannot finish is `NotConverged` and is left out of
    `ModerateContrasts`. It matches R to 1e-5. The default stays non-robust.
  - **`NestedMixedModelProblem.FromNuisanceLabels`** (#1519) builds a problem from peptide labels. It drops non-finite
    responses and treatment-codes against the first label in ordinal order. `NuisanceLevels` names the coding.
- **`FragmentCoElution`** (#1503): `Smooth`, `SavitzkyGolay9`, `BestFragment`, `CorrelationsTo`, `ApexScores` and
  `FindApexes`. These are the scoring steps MetaMorpheus's DIA search calls.
- **GO stored once per database (#1497)** — `GoAccessionAnnotation`, `GoAccessionTermsTsv`, `GoOntologyTsv`,
  `GoCategoryTsv.Write`/`Read`, and the `UsefulProteomicsDatabases.Annotation` namespace (`MemberResolver`,
  `MemberResolution`, `AnnotationTable<T>`).
  - Per database: 42 MB of direct annotation, plus 11.5 MB of ontology closure per `go.obo`.
  - Per search: 188 KB of member resolution, in place of a 199 MB per-search file.
  - The new readers are strict and throw on bad input. `GoGroupAnnotator` gains a constructor over the stored tables.
- **PRIDE:**
  - `DownloadProjectFilesByNameAsync` downloads named files only. It refuses, before downloading anything, any name the
    project does not hold, and names every missing one.
  - A `verifyMd5` overload of `DownloadProjectFilesAsync` (#1518).
- **`DatabaseReference.Molecule` and `UniProtSequenceAttributes.DisplayedIsoformId`** (#1501), each with a new
  constructor; the old constructors stay.
- **`DissociationType.IsCid()`** (#1311) is true for CID and LowCID. The b1 skip in fragmentation now uses it. No
  fragmentation answer changes.

## Performance

**Spectra-file reading, spectral averaging, FlashLFQ and digestion are faster, with identical output (#1479).**

**Measurement:** candidate and master ran at the same time on one machine, each on its own 16-thread CCD, swapping
slots every repeat. A/A noise is ±1% CPU and ±10% wall. The ratios are candidate ÷ master. They measure this PR
**together with** the MetaMorpheus speed PR (trishorts/MetaMorpheus#32), which waits for this release.

| Workload | CPU ratio | Wall ratio |
|---|---|---|
| astral-250pg, 18 files | 0.36 | 0.36–0.37 |
| Jenkins bottom-up | 0.49–0.51 | 0.48–0.52 |
| Jenkins top-down | 0.46 | 0.37–0.41 |
| Modern search, bottom-up | 0.77–0.78 | 0.70–0.72 |

**This PR alone:**

| Step | Before | After |
|---|---|---|
| 1.9 GB raw-file hash | 3.4–4.2 s | 2.7 s |
| 378 MB indexed mzML | 11.3–14.5 s | 3.6–3.8 s |
| Top-down digestion | 16–17.5 s | 2.7–3.3 s |
| timsTOF 1.6 GB `.d`, 11 threads | 32.9–38.6 s | 18.6–20.4 s |

Spectral averaging is about 4× faster with 18× less allocation.

**Output is identical:**
- Every output file of every repeat was byte-identical, once paths, timestamps and mzML checksums were masked.
- Jenkins bottom-up: 30,652 PSMs / 11,191 peptides / 3,705 protein groups on both sides.
- FlashLFQ tables are byte-identical to 1.0.594 at 1 and 12 threads.

Behaviour that comes with it:
- **`PeptideWithSetModifications.FullSequence` is built on first read for digested peptides.** Public constructors
  still build it at once. A binary serializer must read it before serializing, or it writes null. MetaMorpheus's
  index writer does this since MetaMorpheus#2912, which is on its master.
- **FlashLFQ with match-between-runs keeps its peak index in memory**, instead of writing `.ind`, while that keeps
  memory load at or below 50%. `IFlashLfqIndexingEngine.SerializeIndex` no longer promises a file on disk.
- **A raw file's SHA-1 is cached per process**, keyed on path, length and last-write time. A file rewritten in place
  with the same length and timestamp keeps its old hash.

## Fixes

- **Koina library spectra for modified peptides (#1392).** Under `MapToValidatedFullSequence`,
  `GenerateLibrarySpectraFromPredictions` threw on every modified peptide ("Could not find modification while
  reading string: …C[UNIMOD:4]…"). See **Breaking changes** for what it now needs.
- **A damaged PRIDE download stops at the first sight of EBI's error text (#1517).**
  - The checked `DownloadFileAsync` used to download the rest of a doomed file. With `verifyMd5`, it failed only when
    the MD5 did. It now discards the partial file and retries from byte 0, within the existing budget.
  - Across 1,962 logged downloads, 22% of 2–3 GB copies were damaged, and each cost 10–40 minutes before being thrown
    away.
  - With `verifyMd5: true`, a file whose own bytes contain EBI's error marker is now refused even when its MD5 matches.
- **`SpectralLibrary.TryGetSpectrum` reads its buffer under the lock its adds and evictions take (#1525).** Before, a
  parallel search could throw (`NullReferenceException`, `IndexOutOfRange`) or read a wrong entry. Callers need do
  nothing.
- **`ModeratedContrast`'s documentation covers `NestedMixedModel` results (#1498).** Documentation only.

Test and CI only: **#1530** raises the `build` job's timeout from 30 to 45 minutes. The suite now takes about 27 minutes
under coverage, and five runs were cancelled at 30 with no test failing.
